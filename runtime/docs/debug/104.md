# 104: kernel_threads.sleep_ns_and_sleep_svc fails under a parallel ctest run, and shell heredocs eat backslashes

**Symptom 1.** `ctest -j4` on a loaded machine reported `g_dt0.load() < kMs` failing in `kernel_threads`; run alone the group passes 29 of 29.

**Cause 1.** A timing assertion on a 1 ms sleep while other test processes, builds and an emulator compete for the CPU. Unrelated to the test tooling (the virtual clock is off in that test). Rerun the group alone before calling it a failure.

**Symptom 2.** A test containing the path `"tt_test_out\\result.json"` written through a shell heredoc failed although the code was right.

**Cause 2.** The shell tool collapsed `\\` to `\`, so the source held `"\r"` (a carriage return) in the path.

**Fix.** Write C++ sources that contain Windows paths with the editor tools, or use forward slashes (the runtime accepts both).
