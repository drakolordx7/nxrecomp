# 401 Every memory pool import costs 30 to 100 ms in the driver, whatever its size

Symptom (S18): a gameplay boot creates about 200 pools under 1 MB; the single import thread took 40 to 100 ms per pool, so the render thread waited behind the queue. At cap 120 the 124 intervals over three times the median in a gameplay run included 42 (5.0 s in total) that overlapped a `pool.import` zone.

Cause: pools are imported with `VK_EXT_external_memory_host` at the pool's own address, which is inside the primary view of the heap section (a pagefile-backed section of several GiB reserved with `SEC_RESERVE`). The driver's `vkGetMemoryHostPointerPropertiesEXT` and `vkAllocateMemory` both walk the mapping that contains the range, so the cost follows the size of the whole view and not of the pool. Stand-alone measurement on the RTX 3080 (8 GiB section, 512 MB committed; a 64 KB range each): primary view 8.6 ms plus 8.2 ms; a separate small view of the same section pages 0.00 ms plus 0.05 ms; plain `VirtualAlloc` memory 0.00 ms plus 0.04 ms. In the game the section holds more committed memory and the cost is 30 ms plus 30 ms. The same kind of walk is behind the `VirtualQuery` cost in `[memory] fast_query`.

Fix (`src/mem/memory.cpp` `heap_private_view`, `src/gfx/nvn/nvn_gpu_pool.cpp`, `[nvn] pool_view`, default on): the importer maps a private view of exactly the pool's section pages (rounded out to 64 KiB, outside the guest-visible alias region), imports that, and unmaps it when the pool is destroyed. All views of a section share the same pages, so CPU and GPU still see one memory. Pools outside the primary view keep the old path. Several import threads were tried first and made each import slower (the driver serialises them).

Measured (gameplay run, same exe, `NXRT_NVN_POOL_VIEW` 0 and 1): pools under 1 MB, median import 63 ms (p90 75) before and 0.19 ms (p90 0.29) after at cap 60; 42.5 ms and 0.22 ms at cap 120. Total import time over the run 12.1 s before, 0.5 s after. Intervals over three times the median that overlap a pool import at cap 120: 42 before, 4 after. The two large pools (360 and 580 MB) still take 110 and 190 ms once, at load.
