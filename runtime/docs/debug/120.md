# 120 Debug 018 root cause: no lazy binding was involved

Symptom (018): GUEST TRAP "indirect call to an address that is not a known function (0x2bd1f0002bd0f9)" on the graphics thread, reported next to the rtld lazy resolver (rtld+0x138c / 0x1318 / 0x8b0).

Cause: not the resolver. Three facts, each checked:
1. The call stack frame `f_770000138c` was a stale `c->fn`: the host stack of the crash is `trap <- dispatch_call <- f_750046f13c+0x99`, the sdk function itself. `f_750046f13c` calls PLT stub 0x58b870 (GOT slot 0xc8a4b0, symbol NvRmGpuDeviceZbcGetActiveSlotMask, defined in the sdk). The lifter lowers a PLT stub whose symbol the module defines to a direct call (`f_750058b870 -> f_750041e3e0`); the stub never reads the GOT. `f_750041e3e0` is `ldr x8,[x0]; ldr x2,[x8,#0x88]; br x2`, a vtable thunk.
2. x0 was an NvRm object whose first word is 0x75ffffffff (not a vtable). `[x8+0x88]` = 0x7600000087 is inside subsdk0's header: 0x002bd1f0002bd0f9 are bytes of the module header. So the SDK's NVN driver used an object its own initialisation had failed to build (our nvdrv answers); it is the real driver code running on stub service answers, not a linker problem.
3. With `[boot] trace_plt = 1` (traced_resolver wrapper at rtld+0x1318 in mpr_main.cpp) zero lazy bindings go through rtld during the whole boot. Cross-module calls are `host_import()` in the lifted PLT stubs (registry lookup at call time), same-module calls are direct. rtld still relocates the GOT, but no lifted code reads it.

Consequences:
- "Other lazily bound sdk/subsdk0 calls will hit the same path" is false: there is no lazy path. An entry hook or `fn_register` override at an address only intercepts calls that go through `call_indirect` (function pointers, vtables, imports through `host_import`), never a direct `f_xxx(c)` call inside the defining module.
- To redirect an import of main into the host, `module_override_symbol(name)` is the working mechanism (`host_import` honours it first); `fn_register(sdk_definition, handler)` additionally covers indirect calls by address. `mpr_main.cpp` does both for `nvnBootstrapLoader`.
- No lifter bug. (The only lifter note is the one already made: rtld has no function at 0x138c, S6.md.)

Fix: route `nvnBootstrapLoader` to the runtime NVN front end (S6b.md). The SDK driver is never entered, so the object that crashed is not built.
