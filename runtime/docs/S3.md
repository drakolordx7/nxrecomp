# S3 log: OS/HLE runtime skeleton

S3 covers the game-independent runtime of the Metroid Prime Remastered recompilation, in this repository. No game binary was available at this stage, so every check ran on a synthetic AArch64 ELF and on stand-in host functions.

## Result (2026-10-21)

- 17 CTest groups, 255 test cases, all pass in a clean Release build (`pwsh scripts\build.ps1 -Clean -Test`, about 28 s). Three further full CTest runs in a row were identical.
- Rerun: `pwsh scripts\build.ps1 -Test`. One group: `build\release\nxrt_tests.exe <group>`.
- ABI header: the real one, `recomp/include/nxrecomp/ctx.h` (ABI version 1). A temporary shim was written first and deleted once S1 published the header.
- Defects found by review or by the tests are recorded in `docs/debug/`.

## Decisions

- Namespace `nxrt`, C++20, Win32 threads (not std::thread) so affinity and priority are settable. Generated-code ABI functions are `extern "C"` in `src/core/abi_glue.cpp`.
- Memory layout (include/nxrt/memory.h): main 0x7100000000, HLE thunks 0x7400000000, SDK 0x7500000000, heap view 0x7800000000 (8 GiB), alias views 0x7A00000000, stacks 0x7C00000000, kernel region 0x7E00000000. The test exe links with `/HIGHENTROPYVA:NO` to keep host allocations low.
- Two synchronisation layers: kernel semantics at SVC level (ArbitrateLock, WaitProcessWideKey, WaitForAddress, in `kernel_sync.cpp`) for the default "recompile the SDK" mode, and a guest-address keyed side table (`sync.h`) for HLE'd nn::os. The condition variable in the side table is a FIFO of waiter nodes: the first version could let a late waiter steal a broadcast token (debug note 001).
- Result codes from Atmosphere `svc_results.hpp`. An unknown SVC answers 0x4201 (ResultNotImplemented). A stub service answers 0x0BCBD5, which is not a Horizon value, so it is recognisable in logs.
- MapMemory/UnmapMemory copy the data and make the source inaccessible instead of aliasing, because the stack region is one host reservation and a view cannot be mapped into a reservation. Heap decommit makes the pages PAGE_NOACCESS because MEM_DECOMMIT fails on section views.
- Thread model: HOS priority 28..59 maps to nn::os 0..31; six Windows bands under the console core model (<=4, 5..8, 9..15, 16, 17, 18+), dynamic boost off; processor slot of six host processors per process taken through a named mutex, three cores picked from the top, one per physical core.
- TLS: per thread a 0x1000-byte TLS region (TPIDRRO_EL0) and a static TLS block (TPIDR_EL0) with the first PT_TLS image at tp + 16 rounded to the segment alignment; thread pointer also stored at TLS + 0x1F0.
- The linker map format parsed is the one lld-link writes (CMake picks lld-link with clang-cl here).
- Scripts live in `scripts/`, not in the root `.weaver/` folder. `scripts\build.ps1` could also be listed in `.weaver/INDEX.md`.

## Gaps

| Gap | Why |
|---|---|
| `nx_catch_call` is a stub: the body runs without a catch frame | needs the lifter's NxEh tables and an unwinder (S1 side); marked in `src/core/abi_glue.cpp` |
| `host_import(c, sym)` finds the module through `c->fn`, falling back to the first module with enough symbols | the ABI passes a module-local DynSym index with no module id; the lifter should make it unique |
| Guest-side servers (CreatePort, ReplyAndReceive, AcceptSession) and light sessions are not implemented | logged as unknown SVCs; no known need yet |
| `RegisterService` of `sm:` answers the stub error | a guest-provided service is not supported |
| GetInfo values (memory sizes, priority mask) are plausible constants, not measured on hardware | only the dump can confirm them |
| `SignalToAddress` type 2 and `WaitForAddress` type 1 with timeout 0 follow the Wonder implementation; Switchbrew does not state the rules | checked by tests against the implementation only |
| kernel TLS and stack memory is a bump allocator and is never returned | 12 KiB per created thread; acceptable for a game that creates tens of threads |
| Windows exclusive-reservation limits: `heap_decommit` leaves pages charged to the section | `memory.cpp`, see debug note 004 |
