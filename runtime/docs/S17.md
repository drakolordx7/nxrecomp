# S17: button prompts

Branch `prompts`. This work area fixed the broken button icons and added a choice of prompt styles.

## What was wrong with the icons

The round A and B icons were drawn as a half circle with stray marks. The cause was not fonts. The game never asks the system font service (`pl:u`) for anything: no `nn::pl` import in `main`, no `pl` line in the log. The icons are ordinary 36x36 BC7 textures (`TXTR_ButtonA`, `TXTR_ButtonB`, `TXTR_ButtonL` ... `TXTR_DPadIdle` in `GuiSysMP1.pak` and `PreloadFrontEndMPT.pak`), drawn through the `fs 71cdc0be...` shader.

The texture data was untiled with the wrong block height. A block-linear texture has a block height in GOBs, and the game's data is laid out with the console's rule (1.5 times the block rows against 16, 32, 64 and 128, the rule `retrotool` tiles with). The back end used the smallest height that covers the rows. A 36 pixel BC7 texture has 9 block rows: the console uses 1 GOB, the back end used 2. Both give the same storage size, so the size checks of S4 never saw it, but the texels land in the wrong place. Of the 6937 non-3D textures of the game, 263 are affected (173 of them are the 36x36 icons, plus 440x300, 80x80 and 128x36 UI textures).

Evidence: `TXTR_ButtonA` decoded with `retrotool` is a clean circle with an A. Untiled with 1 GOB it matches; with 2 GOBs it is the half circle with black blocks. The traced title frame shows the icon drawn by draw 46 from texture 158 (36x36 BC7). After the fix the title prompt "PRESS (A) TO START" renders clean (`work/run_prompts/crop_title2.png`, before: `crop_title.png`).

Fix: `console_block_height()` in `src/gfx/nvn/nvn_texture_layout.cpp` replaces `tegra::default_gob_blocks_y` for 2D textures without a packaged layout. Test expectations that had been worked out with the old rule were updated (`test_nvn_texture.cpp`: ASTC 8x5 100x100 alignment 1024, the R8 20x20 array 6144 bytes at 1024). A real-data test (skipped without the paks) checks that the untiled icon has no all-zero BC7 blocks with 1 GOB and some with 2.

## Prompt styles

`controls.ini`:

```
[prompts]
style = switch      ; switch (the game's own icons, default), xbox, playstation, keyboard, auto
```

The F1 page has a "Button prompts" combo on the Controller tab, and with Auto it shows which style is in use.

| Style | What is shown |
|---|---|
| switch | The game's own icons. Nothing is replaced. |
| xbox, playstation | The Xbox or PlayStation button that presses the Switch button. With `[pad] label_abxy = 1` Switch A is Xbox A or cross; with 0 the position rule applies (Switch A is the east button: Xbox B, circle). L, R, ZL, ZR are LB, RB, LT, RT or L1, R1, L2, R2; plus and minus are menu and view or options and create. |
| keyboard | The key or mouse button that is bound to the action behind the Switch button. The resolver takes actions whose `[switch]` output is exactly that button (confirm and back before the raw `btn_` actions), looks in the bindings of the current context, then in the other contexts, and follows rebinding. A button nothing is bound to (X in the default layout) keeps the game's icon. |
| auto | Keyboard and mouse after the last keyboard or mouse input, otherwise the kind of the pad used last (PlayStation, Switch, everything else counts as Xbox). Before any input: a connected pad's kind, else keyboard. |

The pressed (gold) icons the game draws while a button is held get the same treatment, with a gold tint of the replacement.

How it works: the back end asks a hook (`include/nxrt/tex_override.h`) about every small single-level BC7 sRGB texture it uploads. `src/gfx/play/prompts.cpp` recognises the 17 icon textures by a hash of their tiled bytes. It learns the hashes at first use from the player's own paks (the RomFS folder, through the setup tool's `pak.cpp` and `txtr.cpp`), so no game data is in the repository. It answers with the pixels of the resolved icon, which the back end encodes to BC7 at 36x36. When the style, the context, the bindings, the label mode or the last device change, the icon textures are uploaded again; no restart.

## Icons

Kenney "Input Prompts" 1.5a, CC0, https://kenney.nl/assets/input-prompts. `scripts/build_prompt_pack.py` turns the Xbox Series, PlayStation Series and Keyboard & Mouse sets into `assets/prompts/prompt_icons.pak` (540 entries of 36x36 RGBA: 270 icons and their pressed twins; 248 keyboard and mouse entries cover every SDL scancode name, 151 of them baked as short text on a blank Kenney key cap). Licence: `assets/prompts/LICENSE-Kenney-InputPrompts.txt`. Rebuild command is in `assets/prompts/README.txt`.

The pack is searched in `[prompts] dir` (env `NXRT_PROMPTS_DIR`), `<exe folder>/prompts/`, `assets/prompts/` under the working directory and the exe folder. A release package must carry `prompts/prompt_icons.pak` and the licence file next to the exe.
