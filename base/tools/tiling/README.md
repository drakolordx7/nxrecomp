# tools/tiling: Tegra block-linear tile / untile

C++20 library (`include/tegra_tiling.h`, `src/tegra_tiling.cpp`), a small CLI (`tegra_tile`) and the tests. It converts
between the Switch GPU's block-linear texture layout and plain rows, for every level, array layer and 3D slice.

## What it covers

- Bytes per block 1, 2, 4, 8, 12, 16; block footprints 1x1 (plain), 4x4 (BCn), 4x4 to 12x12 (ASTC).
- Block height of level 0 from 1 to 32 GOBs and block depth from 1 to 32 (3D), both powers of two. Small mips shrink the block height
  the way the hardware does (`gob_blocks_y` halves while the level fits in half a block); 3D mips halve the depth block once per level.
- Mip chains, array layers (2D), 3D textures with depth, partial GOBs at the right and bottom edges.
- Linear buffer layout identical to Ryujinx's (levels back to back, then layers, then z, then rows padded to 4 bytes);
  `linear_stride_align = 1` gives tight rows.
- Block height is an input. Packaged (BNTX) textures carry their own value (BRTI +0x34, `1 << (layout & 7)`), which is
  often one step smaller than `default_gob_blocks_y()`; use the file's (see `refs\SuperMarioWonderRecomp\docs\nvn\TILING.md`).
- Not covered: tile width above 1 (`gobBlocksInTileX`), 3D arrays, pitch-linear textures. The code is single-threaded: 4.5 to 5 GB/s on a
  4096x4096 RGBA8 level on the i9-12900K (`tiling_test bench`).

```cpp
tegra::TextureDesc d;  d.width = 1920; d.height = 1080; d.levels = 11; d.bytes_per_block = 16; d.block_w = d.block_h = 4;
d.gob_blocks_y = 16;
tegra::Layout l = tegra::compute_layout(d);        // per-level offsets, sizes, effective block heights
tegra::untile(d, l, tiled, linear);                // or tile(); untile_level()/tile_level() for one level
```

CLI: `tegra_tile untile in.bin out.bin --width W --height H [--depth D] [--levels N] [--layers L] --bpb B [--block WxH] --gob-y G [--gob-z G] [--tight]`.

## Build and test

```powershell
pwsh -File tools\tiling\scripts\build.ps1                       # CMake + Ninja + clang-cl -> build\release
powershell -File tools\tiling\scripts\setup_ryujinx.ps1         # once, for the Ryujinx reference tool
tools\.venv\Scripts\python.exe tools\tiling\oracle\run_oracle.py [--regen]
```

## Oracle

`oracle/run_oracle.py` prints `ORACLE PASS` only when all of these hold:

1. `scripts/verify_layout.py` (a numpy re-derivation of every address, independent of Ryujinx and of the library) accepts the generated cases.
2. `tiling_test crosscheck`: for 332 cases generated by `ref/RyuTilingRef` (a C# program that calls Ryujinx's
   `LayoutConverter` / `SizeCalculator` on deterministic pseudo-random data), the library's layout sizes and per-level offsets
   equal Ryujinx's, `tile()` reproduces Ryujinx's tiled bytes exactly (padding included) and `untile()` returns the original.
   The matrix: bytes per block 1/2/4/8/16, 1x1, 4x4 and ASTC 5x5..12x12 blocks, block heights 1..32, 8 sizes from 1x1 to 1920x1080, single level and full mip chains, 1/2/6 layers, 3D depths 1/4/9/16 with block depths 1..16. 20,455,125 blocks compared.
3. `tiling_test roundtrip` (3 seeds, about 5,900 textures each, roughly 90 million blocks): tile then untile is the identity on every valid
   byte, and every byte sits where an address formula written separately from the converter says it should, including bytes per block 12, block heights up to 32 and 3D depths up to 33.

Result on this machine: ORACLE PASS (332 cases, 0 failed; 5,944 / 5,926 / 5,940 round-trip textures, 0 failed).
