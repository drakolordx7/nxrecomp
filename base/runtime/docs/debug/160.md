# 160 The game presents from its own thread, not the one that runs Update

The Update hook (frame boundary) runs on the guest main thread, which is the host main thread that created the window. NVN presents come from another guest thread (`guest-88` in the log, `nvn-render` inside the back end). So: SDL events can be pumped from the Update hook, but anything that touches the swapchain (`Renderer::set_present_mode`, which recreates it) must run on the presenting thread. `FrameLimiter::set_pre_frame_hook` runs a function at the top of every `begin_frame`, on that thread, and play mode applies present-mode changes there. The ImGui overlay is fed on the main thread and drawn on the presenting thread, so `overlay.cpp` now holds a mutex around the ImGui context. Fullscreen goes through SDL on the main thread; the renderer picks the new size up through its normal out-of-date path.
