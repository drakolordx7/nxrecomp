# 103: the bring-up determinism oracle does not exercise the clock

**Symptom.** Two `mpr.exe` runs with `deterministic=1` give identical per-frame hashes, but a run with `deterministic=0` gives the same hashes too.

**Cause.** The game stops at the first missing service after about 60 SVCs and has stored nothing time-dependent in the hashed regions (module images, heap, kernel region) by then.

**Fix.** Nothing to fix. The clock, the RNG and the wall-time epoch are proven by the `tt_core` unit tests. Rerun the `suites/boot.toml` oracle once the game reaches its main loop, with `frame_source=hook` and a heap region in `hash_regions`; that is where the clock starts to matter.
