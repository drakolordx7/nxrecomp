# 102: eden-cli with an unquoted path spins with no window

**Symptom.** `eden-cli.exe -g <nsp>` started from PowerShell burned one core, showed no window and wrote an empty log.

**Cause.** The NSP path contains spaces and parentheses; passed unquoted through `Start-Process -ArgumentList` it was split into several arguments. Separately, `eden.exe --help` opens the GUI and never returns, which hung a shell for two minutes.

**Fix.** Pass the path as one argument (a list in Python, `subprocess.Popen([exe, path])`, or an escaped quoted string in PowerShell). The game path is a bare argument. Never run `eden.exe --help` from a tool call. Two harness runs at once collide on the GDB port and the frame folder: run one at a time.
