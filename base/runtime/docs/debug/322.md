# 322 Scripted runs need real time and a fixed step, not the virtual clock

Symptom: the deterministic mode (virtual clock, one frame = 1/rate) made the front end and area loads six times slower (a New Game took 600 s instead of 100) and the game step in gameplay was not 1/rate: the guest threads' sleeps advance the shared virtual clock, so the measured frame time was inflated and the step hit its clamp.

Fix: scripts load in real time and measure with `@rate hz`, which makes the game's step exactly 1/hz for every frame (`timestep::set_run_rate`); the clock stays real. In a real run the trace shows 1/60 and 1/144 game seconds per frame and 4 s walks of 32.58 and 32.53 units.

Also found: while a front-end screen waits for a press, a press of 40 frames (about 44 ms of host time at hundreds of frames per second) is too short; `@mash` holds the press for 250 ms of host time. The watchdog (10 s) fires on slow area loads under load; scripted runs set it to 60 s.
