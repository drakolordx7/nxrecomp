# 017 Two services disagreed about the byte order of a Uid

Symptom: with the real game, `acc:u0` GetBaasAccountManagerForApplication answered UserNotExist for the user id the game had just read from the preselected-user launch parameter; later fsp-srv OpenSaveDataFileSystem said the save did not exist.

Cause: `acc` writes and compares a Uid as (uid_hi, uid_lo) in memory order, `am` wrote the launch parameter and read EnsureSaveData arguments as (lo, hi), then passed them to fsapi swapped.

Fix: one rule for every service: the first u64 of a Uid in memory is uid_hi, the second uid_lo (profile().user_uid_hi / _lo). Tests: `svc_boot_flow.startup_user_id_agrees_between_am_acc_and_fs` replays the game sequence across the three services.
