# 006 module_override_symbol left resolved imports pointing at the old target

Symptom: an import that had already been called once (and so resolved to another lifted module's function) kept running that function after `module_override_symbol(name)` forced the symbol to the host. Found by `nxmodule.override_after_first_resolution_invalidates_cache`, written once the bug was reproduced in `tests/test_nxmodule.cpp`.

Cause: `host_import` resolves an (module index, symbol) pair once and caches the target per DynSym (`src/core/nxmodule.cpp`). Registering a module cleared the caches, overriding a symbol did not, although the header promised it.

Fix: `import_cache_invalidate()` (nxmodule.h), called by `module_override_symbol`.

Consequence: overrides can be added at any time; the next call of each import re-resolves. Lock-free readers see either the old or the new target for the call in flight.
