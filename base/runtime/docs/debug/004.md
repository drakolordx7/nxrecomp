# 004 Heap decommit on a section view, and MapMemory into a reservation

Symptom: `VirtualFree(MEM_DECOMMIT)` on pages of the heap view failed with error 87. A second problem of the same kind: an alias view cannot be mapped at an address inside a `VirtualAlloc(MEM_RESERVE)` region.

Cause: Windows only decommits pages of a view of a pagefile-backed section through the section, not with VirtualFree on the view. MapViewOfFileEx needs free address space, not a reservation.

Fix: `mem::heap_decommit` sets the primary-view pages to PAGE_NOACCESS and clears them from the committed bitmap (the pages stay charged to the section; alias views still see the data). svcMapMemory copies the data into the destination (committed inside the stack reservation), makes the source PAGE_NOACCESS and copies back on svcUnmapMemory.

Consequence: a guest that maps and unmaps large heap ranges repeatedly costs copies and does not return memory to the system. Revisit with placeholder reservations (VirtualAlloc2 / MapViewOfFile3) if the game does this often.
