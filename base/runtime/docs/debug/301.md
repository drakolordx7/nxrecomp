# 301 Front-end screenshots at the same game time differ between rates, with no timing error

Symptom: `hifps_probe.py menu` takes screenshots of the title screen and the first attract movie at the same virtual times for 60, 120, 144 and 240 steps per second. The layout matches but the ssim against the 60 Hz run is only 0.3 to 0.9. The title shot at 22 s shows the same screen with the video background at another point of its loop.

Cause: loading takes real time. In deterministic mode game time advances one step per frame, and the machine renders roughly the same number of frames per real second whatever the virtual rate. A load of a fixed real duration is therefore a fixed number of frames, which is a shorter stretch of virtual time at 240 steps per second than at 60. The title movie starts at a different game time in each run. Everything on the front end is a movie (title, menu backdrops, attract clips), so screens at equal virtual times are in different phases.

Resolution: screenshot equality is the wrong check for the front end. The check is the movie player's consumption rate and the sum of the steps per virtual second (`hifps_timing.py`, 1.000 at every rate). The `menu` scenario stays as an informational run.
