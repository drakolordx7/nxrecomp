# 014 Release message closed the client handle

Symptom: with the real SDK, `nn::pctl::Initialize` aborted inside `nn::sf::hipc::CloseClientSessionHandle` (svcBreak, result 0xE401 InvalidHandle) right after the first service object was released.

Cause: `ipc::send_sync_request` handled the CMIF Release message (type 2) by closing the session handle itself. The SDK, like libnx, sends Release and then calls svcCloseHandle on the same handle; the second close failed and the SDK aborts on a failed CloseHandle.

Fix: Release now only answers with an empty message and leaves the handle alone; the service sees `on_close` when the handle is closed (KSession destructor). `ipc.release_keeps_the_handle_until_closed` replaces the old test that expected the handle to be gone.
