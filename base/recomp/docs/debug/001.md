# 001 LDSMAX / LDSMIN of 8, 16 and 32 bits differ from Unicorn

**Symptom.** After the LSE handlers were written, 964 tests of 80 shapes (`ldsmax`, `ldsmin`, `stsmax`, `stsmin`, sizes b, h, w, all orderings) failed. 64-bit forms passed. Every failing test had operands of opposite sign.

**Cause.** Unicorn 2.1.4 (QEMU) executes the sub-64-bit signed forms with an unsigned comparison. Reproduced directly: `LDSMAX w1, w2, [x0]` with memory 1 and operand 0xffffffff stores 0xffffffff. The Arm ARM defines them as signed. The lifter was right.

**Fix.** The oracle takes the result for exactly these instructions from the architectural definition (`smaxmin_fields` / `spec_smaxmin` in `oracle/difftest/difftest.py`, applied to Unicorn's final state: the memory word and Rt). Everything else is still Unicorn's. Listed in GAPS.md as a reference correction.
