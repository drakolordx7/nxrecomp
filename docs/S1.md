# S1 (recompiler) log

Log of what was built, in order, with the decisions that were not planned in advance. Numbers are from runs on this machine.

## Design

- **Fork base:** smo-recomp's lifter. Its instruction translator became tier 1 (`lift/a64.py`); the program level became
  `program.py` on top of an `Image` abstraction (`image.py`), so an NSO, smo's ELF form, or an ordinary static ELF all lift the
  same way. The last one is what makes the end-to-end oracle possible without a game binary.
- **Output language: C++20**, not smo's C. Reason: the Wonder emitters (the best instruction coverage found) emit C++ against a
  helper header; porting them to C would have been a rewrite. The runtime ABI header (`ctx.h`) stays valid C and C++.
- **Two tiers.** Tier 1 (bit-field decoder) wins where it applies; tier 2 (Capstone-driven, ported from Wonder) takes the rest.
  Tier-2 handlers were fixed and added in `x_*.py` mixins that come first in the class order, so the ported files
  stayed as they were.
- **Per-game seam:** `games/<name>/config.py` (modules and bases, overrides, extra entries, patches). `games/mpr` is a placeholder.
- **Build:** CMake + Ninja + clang-cl. `nxrecomp_add_module()` lifts as a build step into a fixed number of shards.

## Timeline

1. Scaffold and ABI header (`include/nxrecomp/ctx.h`) committed first, so the runtime work could read it.
2. Image / function discovery / lifter skeleton; smo's tier 1 running on test ELFs: 13 of 24 end-to-end cases passed at once.
3. Differential oracle: a corpus generator (random words, closure over single-bit flips, filtered by what Unicorn's Cortex-A57
   executes) replaced smo's "sample the game binary". 11,603 shapes, 606 mnemonics. First full run: 2,528 untranslated shapes.
4. Tier 2 ported from Wonder. Untranslated dropped to 363 shapes, differences to 9,018 of 324,642 tests.
5. Six instruction families were implemented and verified (FP exactness, LSE, vector loads / stores, narrowing / saturating NEON,
   remaining integer NEON, FP misc). Each was checked with the differential test filtered to its shapes. Fixes made in
   between: clrex, FPCR / FPSR masks, PRFM-versus-LSE decode, XTN2, jump tables, C++ exception runtime, site lists.
6. Oracle hardening: the reference correction (Unicorn's unsigned LDSMAX), integer collision states, byte sweeps for AES, special
   values near the saturation bounds, hand-written trap / system-register / exclusive-sequence tests, planted-bug test.
   Each hardening step was driven by a planted bug that the previous version did not catch (4 of 22 at first). The stronger
   states then found three real lifter bugs (FRSQRTS overflow in the fused step, FCVTL of a signalling half NaN, SQDMLSL
   saturation order).

## Decisions not planned in advance

- C++ output (above); ABI version 2; import ids `NX_IMPORT_ID(module, sym)`; `NxModule` descriptor instead of smo's loose tables.
- Every test runs on Unicorn's Cortex-A57 model (the console's CPU); only the LSE atomics use the `max` model.
- Corpus scope = what Unicorn's A57 executes, plus LSE. SVE / SME and the ARMv8.1+ extensions are counted as out of scope.
- Unicorn correction: exactly the sub-64-bit signed LDSMAX / LDSMIN family (docs/debug/001.md).
- FPCR: stored and masked to the A57 bits; not honoured. FPSR: stored; sticky flags not tracked.
- `dmb` / `dsb` are seq_cst fences; LDAR / STLR are acquire / release atomics.
- Hook sites: `entryhook`, `midhook`, `inline`, `dynimm`, `noinline`, `patch`, `jtable`; the runtime implements `nx_hook_entry`,
  `nx_site_inline`, `nx_site_midhook`. ssbu's `hook_inline_check.py` is replaced by `noinline` on hooked entries.
- Not ported on purpose: SMO's `sdklift`, `gen_tables`, NPDM / version checks, nerve naming, clang-9 scripts.

## What the runtime must implement for C++ catch

1. `__cxa_throw` / `_Unwind_Resume` / `__cxa_rethrow` of the game's own libc++abi are lifted guest code; they end in the
   unwinder. In the real runtime the unwinder is the runtime's own code that those guest functions call (or that replaces them
   as imports); the oracle's stand-in is `oracle/e2e/rt/eh_rt.cpp` reached through fixed host-service addresses.
2. The unwinder walks the guest stack with `NxModule.eh` (`NxEh`): FDE by pc; the CFI row at `pc - 1` gives the CFA
   (`x[cfa_reg] + cfa_off`) and the saved registers (x19..x30, v8..v15 low halves) at CFA + offset; the caller's pc is the
   restored x30. For each frame: find the call site covering `pc - 1`; `pad == 0` means keep unwinding; otherwise walk the
   action chain (`filter > 0`: the type is `types[fde.type_first + filter - 1]`, 0 = catch(...); `filter == 0` = cleanup).
   The reference implementation matches typeinfo pointers exactly; the real runtime adds the class-hierarchy match of
   `__cxa` (`__do_catch`).
3. Landing: set `x0` = exception object, `x1` = selector (the filter value, 0 for a cleanup), restore x19..x30, v8..v15 low
   halves and SP from the frame, then resume the lifted function at the pad:
   - the function is entered as `nx_catch_call(c, u_<entry>)` (its `f_<addr>` is that call): the runtime implements
     `nx_catch_call(c, body)` as a setjmp frame keyed by the guest SP at entry (= that function's CFA); the unwinder longjmps
     to the frame whose key equals the CFA of the catching function and calls `body(c, pad)` (loop: the same function may be
     landed in again);
   - otherwise (cleanup-only function): call `u_<entry>(c, pad)` directly from the unwinder (found through `NxModule.resume`,
     sorted by pad); it ends in `_Unwind_Resume`, which unwinds further.
4. `NxModule.resume` lists every landing pad with its resume function.
