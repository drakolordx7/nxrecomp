# 002 svcExitThread leaked the thread object (thread.cpp)

Symptom: `kernel_threads.thread_object_released_after_svc_exit` failed: after `kernel_reset()` the `KThread` was still alive and its host HANDLE open.

Cause: `host_thread_main` held the owning `shared_ptr<KThread>` as a local. `thread_exit()` ends the thread with `ExitThread`, which does not run C++ destructors, so that reference was never dropped.

Fix: the owning reference is a `thread_local` (`t_keepalive`) that `thread_exit()` and the normal return path reset explicitly before the thread ends.

Check: the same test passes, as does the normal-return variant.
