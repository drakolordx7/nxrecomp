# 016 MapSharedMemory only accepted the alias region

Symptom: `nn::time::Initialize` aborted in `SharedMemoryClient`: 25 consecutive svcMapSharedMemory calls at random addresses returned 0xD401.

Cause: the SDK (`StackGuardManager::MapAtRandomAddress`) picks random free addresses in the ASLR region that GetInfo reports (0x8000000 + 0x7FF8000000) and retries until the kernel accepts one. The runtime accepted only the 8 GiB alias region, and, inside it, only 64 KiB aligned addresses (a host reservation starts on a 64 KiB boundary).

Fix: MapSharedMemory, MapTransferMemory and MapPhysicalMemory accept any range below the main image (from 0x8000000) or inside the alias region that the host can give out exactly (the guest layout above 0x7100000000 is kept for the runtime). A page-aligned address reserves the enclosing 64 KiB range and commits the pages; the reservation base is remembered so the unmap releases the right allocation.
