# 010 The NVIDIA driver keeps 5 handles per destroyed VkDevice

Symptom: the soak test that built and destroyed whole renderers lost 5 process handles per round (437 to 469 over four runs). The growth did not depend on validation, the swapchain, SDL or ImGui.

Cause: not nxrt. A probe that only calls `vkCreateDevice` and `vkDestroyDevice` on the RTX 3080 (driver 617.42) with an empty one-queue device leaves 5 handles behind each time (50 handles over 10 rounds). Instance creation alone, device enumeration, and the same calls on the UHD 770 leave none.

Fix: none in the runtime. The leak test (`gfx_present.no_handle_or_memory_growth_over_hundreds_of_swapchain_recreations`) now keeps one device and rebuilds the swapchain about 235 times, which is the case that matters for resize and present-mode switching: handles 681 to 682, private bytes +0.33 MiB. A game creates one device per run, so the driver's 5 handles are irrelevant there. Re-check on a newer driver.
