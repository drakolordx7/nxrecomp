# 070 The lifted rtld has no function at its entry or at 0x138c

**Symptom.** `GUEST TRAP: indirect call to an address that is not a known function (0x7700000000)` on the first instruction of the process; after that was worked around, `0x770000138c` inside `nn::init::Start`.

**Cause.** The lifter finds function starts from `.eh_frame`, symbols and branch targets. rtld has FDEs for its compiled functions only. Two pieces of hand-written assembly have none, no symbol, and no direct branch to them: the entry (offset 0 to 0xd4: `b +8`, the bss clear, the call to the self-relocation at 0x13c0, the call to the dynamic linker at 0x4b0, the call to `nn::init::Start` with five arguments, then `b .`) and the 5-instruction function at 0x138c (`mov x0,x30; bl 0x1398`, which stores 1 at rtld+0x3008). The second is reached only through the pc-relative idiom `bl next; .word off`, and its address is passed to `nn::init::Start` as a function pointer. Everything they call is lifted (43 functions).

**Fix (host side, `game-build/src/mpr_main.cpp`).** `fn_register` of two host functions at those addresses that do exactly what the instructions do (documented instruction by instruction in the source), only when the lifted table has no function there. The proper fix is in the game config of the lifter (`recomp/games/mpr/config.py`, `extra_entries = {'rtld': [0x0, 0x138c]}`); reported to the lead because `recomp/` is not this stream's.

**Check.** Boot reaches `nn::init::Start` and runs the rest of the start-up on the lifted code.
