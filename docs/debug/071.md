# 071 Two linkers: rtld relocates the modules itself

**Symptom.** With the runtime's linker having relocated every module (`module_link_all`), the lifted rtld's dynamic linker (`f_4b0` -> `f_f20`) ended in `svcBreak` (reason 0, from rtld+0x1398).

**Cause.** Horizon's rtld relocates `main`, `sdk`, `subsdk0` after the kernel mapped them (it finds them with svcQueryMemory). For the PLT slots (rtld 0x10ec to 0x1164) it adds the base to the value the NSO holds (the module-relative address of the lazy stub) after checking that value against the resolver address it keeps in the module object (the check that reaches `svc #0x26` at 0x115c); after the host linker overwrote the slots with resolved targets that check cannot hold. RELATIVE entries are idempotent (addend based), JUMP_SLOT entries are not.

**Fix.** The default is the console's way: `[boot] link = rtld`. The host only maps the segments and applies the protections / memory-state records (`module_protect_all()`: svcQueryMemory has to show the modules as code / code data) and lets the game's rtld do all relocations, symbol resolution across modules and the module-object registration the SDK reads later. `[boot] link = host` keeps the runtime's linker (`module_link_all`) and skips rtld's linker step; both reach the same point (nnMain). The runtime's linker now also has a name index (`Module::find_symbol` was a linear scan, 13k ABS64 relocations against 100k symbols) and defines the four linker symbols (`__rel_dyn_start/end`, `__rel_plt_start/end`) as the importing module's own tables.

**Check.** `tools/boot/boot.py` with `--link rtld` and `--link host`: same stop point.
