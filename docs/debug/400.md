# 400 Frame rate decays to 2 or 3 fps over a run when shader blocks are missing: a failed shader link is retried on every bind

Symptom (S18): in a Frigate run of 170 seconds the frame rate held at the cap (60 or 120) for the first 90 to 100 seconds of play, then fell steadily: 40, 20, 12, 8, 5 fps, down to 2 or 3 at the end, with frame intervals of 200 to 600 ms. It did not depend on the cap, on the console core model (`NXRT_SCHED_CONSOLE_CORES=0` behaved the same) or on machine load. The run had no shader cache configured (`NXRT_NVN_SHADER_CACHE` unset, the log says "no shader cache"), so every program stayed unlinked and nothing was drawn; with a complete cache the loop does not start.

What the traces showed (`[prof] trace` with `stall_ms`):

- During the slow phase two guest threads (the render job thread and one worker) pass one guest mutex back and forth: about 4,000 `ArbitrateLock` waits each in 40 seconds, 3.7 ms per wait. Nothing else is busy; the main thread waits for the render job.
- Both stacks are `CMaterial::ApplyShader` / `CShaderCore_NVN::BindShader` -> `EnsureShaderBuilt` -> `BuildFromDelayedData` -> `CGraphicsPoolAllocator::Alloc`. The holder spends its time in the allocator's first-fit scan (`CMemPool::Alloc`: a bit-per-block bitmap searched from the start, over every pool of the allocator).
- The log shows `nvnProgramSetShaders: no translated shader for block ...; program not linked`.

Cause: `BuildFromDelayedData` builds three `NVNManaged::CProgram` objects, allocates a buffer for the shader code from the pool allocator and calls `nvnProgramSetShaders`. When that returns 0 the build fails, `EnsureShaderBuilt` returns 0 and the shader stays "not built", so the next bind of any material that uses it starts the whole build again. Each attempt costs an allocator call under the allocator lock; the scan gets longer as the pools fill, so attempts get slower, and the number of distinct unbuilt shaders in view grows as the player moves on.

Fix (`src/gfx/nvn/api_program.cpp`, `[nvn] accept_unlinked`, default on): `nvnProgramSetShaders` returns success when every stage had a code and a control address but a block is missing from the cache. The program stays unlinked and its draws are skipped exactly as before; the game stops rebuilding. `NXRT_NVN_ACCEPT_UNLINKED=0` restores the old return value for before/after runs.

Measured (cap 60, window 20 to 160 s of the run, same exe, no shader cache): average 38.5 fps, p99 frame interval 207 ms and 448 frames over 50 ms before; 59.4 fps, p99 22.5 ms and 23 frames over 50 ms after. With the full shader cache both settings behave the same (no block is missing), so this protects partial caches and wrong cache paths; a correctly installed game does not hit it.
