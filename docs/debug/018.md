# 018 Real boot stops in a lazy PLT binding (not a service problem)

Symptom: after nvdrv, vi and hid initialise, the graphics thread dies with GUEST TRAP: indirect call to an address that is not a known function (0x2bd1f0002bd0f9) at sdk+0x56cad0.

Finding: sdk+0x56cad0 is a PLT stub whose GOT slot (sdk+0xc7ade8) still holds 0x7700001318, the entry of the rtld lazy resolver, after the earlier calls; the resolver (host stand-in rtld_fn_138c in mpr_main.cpp) returns garbage for that slot. No service request is involved (every request before it succeeded, the IPC trace shows the last ones as nvdrv Close). Reported to the lead (boot stream).
