# 007 Catch clauses vanish from the guest test programs (nounwind inferred for __cxa_throw)

Symptom: the first versions of `tests/lift/progs/*.cpp` built, passed the EXPECT-INSN check and compiled to a `test_main` that was one call to the thrower followed by `unreachable`: every try/catch had been deleted. `19_eh_probe` passed its lifted run with a hollow result, and each program's author found the effect and worked around it in their own file (an inline asm barrier, `#pragma clang optimize off`, a volatile null function pointer).

Cause: `guest/rt2.h` defines `__cxa_throw` and its callees in the same translation unit as the program. LLVM infers `nounwind` for a function whose body cannot unwind, so calls to it become plain calls and the landing pads and handlers behind them are dead code. In real libc++abi the function lives in another translation unit and callers must assume it unwinds. The EXPECT-INSN lines for `__cxa_throw` / `__cxa_begin_catch` are satisfied by the calls inside rt2.h's own bodies, so they cannot detect this.

Fix: `NX_OPAQUE` (`noinline, optnone`) on `__cxa_throw`, `__cxa_rethrow`, `_Unwind_RaiseException`, `_Unwind_Resume` and `nx_host_terminate` in rt2.h; the program-side workarounds were removed. The check that matters is the comparison of results[] with the host's own exceptions, which a hollow program cannot fake: the mutation run (docs/S3b.md) shows 8 of 9 planted runtime bugs are caught by it.

Lesson for new guest programs: never trust EXPECT-INSN alone; look at `test_main` in the disassembly once.
