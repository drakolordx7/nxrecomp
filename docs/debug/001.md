# 001 Condition variable could lose a broadcast wakeup (sync.cpp)

Symptom: none observed in tests. Found by reading the first version of `src/os/sync.cpp`.

Cause: the condition variable counted `waiting` and `tokens`. After a broadcast set `tokens = waiting`, a waiter that registered before the woken ones had re-acquired the guest mutex could consume a token at once. One of the earlier waiters was left without a token and slept until the next signal, so a broadcast did not reach every waiter that was already waiting. Guest code that signals after releasing the mutex hits this window.

Fix: each waiter queues a node (FIFO) with a `woken` flag. Signal marks and unlinks the first node, broadcast marks and unlinks all of them. A timed-out waiter unlinks its own node. A node is touched only under the condition variable's lock.

Check: `sync` group (17 cases, including the stress case) and `kernel_sync` for the kernel-level equivalent.
