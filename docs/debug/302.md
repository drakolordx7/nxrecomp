# 302 240 steps per second on the headless pipeline

Symptom: asking the real clock for 240 Hz (`max_rate = 240`, or `mode = fixed` with `rate = 240`) delivered 100 to 165 frames per second. `fixed` then ran the game at 0.4 to 0.7 of real time and `real` followed the slower frame time.

Cause: the headless render path of the NVN layer is the limit, and other builds were running on the machine at the same time. The delivered rate moved between 52 and 167 fps for one setting from run to run. The play-mode limiter test hit the same ceiling (docs/S8.md: 96 and 90 fps at caps 120 and 144).

Handling: the 240 Hz path is proven on the virtual clock (deterministic mode, `clock_step_ticks = 80000`), where a frame is exactly 1/240 s of game time. Real-clock runs use the movie player's consumption rate, which must be 1.0 at any frame rate the machine reaches, as the pass condition. The step sum is informational there: whenever a frame takes longer than 1/30 s the step is clamped on purpose, so the game slows down instead of taking one large step.

Also seen at 240: the retail 14 ms background budget is longer than the whole frame at that rate. The scaled budget keeps the same share of the frame.
