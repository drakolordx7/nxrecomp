# 122 Services closed the guest's copy handles; present flip; SetThreadCoreMask -1; command-line options lost

1. **Copy handles.** `audren:u` OpenAudioRenderer (audio.cpp), `am` (close_copies) and `network` (close_copied) closed the request's *copy* handles ("they belong to the service now"). HIPC copies them: the guest keeps its handle and closes it itself. `nn::os::CloseNativeHandle` on the transfer memory (0x10037) then got kInvalidHandle and the SDK aborted (svcBreak) right after OpenAudioRenderer. Only move handles change owner (ipc.cpp consumes them). The three helpers are no-ops now; svcCloseHandle logs a warning for a handle that is not open.
2. **Lower-left present.** The game sets `nvnDeviceSetWindowOriginMode(0)` = LOWER_LEFT. With the back end's unflipped present the title screen was upside down; the console shows it upright, so the present step flips when the origin mode is lower-left (`PresentPass::set_flip_y`, shader push constant src.z, `scripts/gen_present_shaders.py`). The geometry origin oracle was updated: the presented picture is upright in both modes, the scissor band of lower-left mode (memory rows 0..11) shows at the bottom. (S4d wrote that the game uses upper-left; it uses lower-left.)
3. **SetThreadCoreMask.** `svcSetThreadCoreMask(handle, -1, mask)` (IdealCoreDontCare; the multimedia library's SfThread does it) returned kInvalidCoreId. -1 is valid; the ideal core becomes the first core of the mask.
4. **Command line.** `mpr.exe --max-seconds / --link / --no-nvn` were set before `nxrt::init()`, which reloads the configuration and drops programmatic values: the deadline never fired. Applied after init now.
