# 009 ABI 3: typeinfo addresses, symbol values, exception specifications, version export

**Symptom.** The runtime stream (S3b) could not rely on three table contents: `NxEh.types` mixed final addresses (indirect slots with a RELATIVE relocation, static images) with module-relative offsets (direct encodings) and silently turned a slot bound to an imported typeinfo symbol into 0, which reads as `catch(...)`; `DynSym.value` was module-relative for NSOs and absolute for static ELFs; `filter < 0` (exception specifications) had no type list; and a stale prebuilt library could not be told from a current one.

**Cause.** The tables were written for the oracle programs, which are static and link every type in.

**Fix.** `eh.parse_lsda_ex` resolves each type slot through the relocation table (RELATIVE: base + addend; symbol relocation: defined here = its address, undefined = symbol index in the new `NxEh.type_syms`), and collects the specification lists the negative filters point at (`NxEh.specs`). `DynSym.value` is a guest address for every input kind. Every module file defines `nxmod_<name>_abi`. `NXRECOMP_ABI_VERSION` is 3. The game's `sdk` has 13 empty `throw()` specifications and no typed catch, so the symbol path is only exercised by the oracles. `parse_lsda` itself is unchanged (the oracle calls it).
