# 009 Validation counters and a busy machine

Two measurement problems found while writing the oracles.

Loader chatter counted as validation warnings. The Vulkan loader reports "Removing layer VK_LAYER_WEOBS_HOOK ... because it is a duplicate" (an overlay tool installed two manifests) through the debug messenger at warning level, and every instance creation logged it. Messages whose id starts with "Loader Message" are now counted as info and logged at debug level. The oracle is about validation errors and warnings from the layer itself.

Frame-rate oracles on a shared GPU. The loop at 120 and 240 fps through the real renderer fell to 80 to 190 fps whenever another program used the GPU (nvidia-smi showed 50 to 98 % utilisation from other processes): the frame waits for the GPU and the GPU is time-sliced between processes, which costs 20 to 100 ms at a time. The limiter's own wake-up accuracy stayed at p99 0.04 to 0.4 ms, max under 1 ms, in every attempt. `gfx_pacing` therefore asserts the accuracy in every attempt, asserts the rate when the loop was limiter-bound (under 0.5 % of frames overran), and reports SKIP, never a pass, when every attempt was disturbed. `gfx_limiter` holds the rates with no GPU involved.
