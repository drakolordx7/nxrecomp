# 443 The environment map mip chain stayed black: the loop check ran before the target had its image

Symptom (log of every gameplay run, `nvn.replay: a texture is sampled while it is a colour attachment of the pass: the dummy texture is bound`, ten `feedback:` lines per process): the game builds the mip chain of its 1024x512 HDR environment texture with full-screen draws. Each draw samples level k-1 and renders level k. The eleven levels are eleven texture objects over one piece of memory, so after the S4f change they share one image. The back end treats a draw that samples the image it renders to as a feedback loop. Note 441 made it copy the image first so the draw reads what the console would read. In the real game that path never ran for the chain: the dummy texture was bound instead, the lower levels were computed from a black input and stayed black.

Cause: `feedback_prepare` runs before the pass for the draw begins. At that point the object that is the render target had no image yet (it receives the shared image when the pass starts and asks for its image), so the object sampled first and the object rendered to looked unrelated and no copy was made. Later, when the descriptors were built, both objects had the shared image, the check now saw the loop and bound the dummy texture. The same-object case that note 441 was tested with did not show the problem.

Fix (`nvn_replay.cpp`, `is_color_feedback`): a colour attachment gets its image before it is compared. `feedback_prepare` also brings the sampled image up to date (`tex_ensure_current`) before it copies it, so storage the game wrote with the CPU reaches the copy too.

Check:
- Test `gfx_nvn_scene_texture.sampling_an_alias_of_the_pass_target_reads_the_copy_made_before_the_draw` (replaces the older test that only required clean validation). Object X holds a pattern and is sampled first; a pass then renders into Y, a second object over the same storage, mirroring X. The window must show the mirrored pattern exactly. It passes (0 of 3,072 pixels off, validation clean) and fails with the check left as it was (3,060 of 3,072 pixels black).
- Gameplay (opening cutscene and hangar): the log has no `dummy texture is bound` line and no `feedback:` line any more (`work/n4/m2sel/mpr.log`; before: `work/n4/m1cut/mpr.log`, 10 lines).
- Rooms look the same before and after (five areas, SSIM 0.98 to 1.00, `work/n4/ab1` against `work/n4/ab2`); only the sharpest reflections read the lower levels, so the rooms tested show no visible change.
