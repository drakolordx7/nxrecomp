# 123 Texture and descriptor stops after the title screen (open, NVN side)

With `[boot] press` driving the pad (A on the title, A on PLAY, A on the next prompts) the game loads and the Vulkan device is lost (VK_ERROR_DEVICE_LOST) a few seconds into the loading screen (~58 s of wall time, mostly ASTC transcoding of ~300 textures, 40..100 ms each). Validation (`NXRT_GFX_VALIDATION=1`) before the loss, most likely cause first:
- VUID-vkCmdDraw-None-08114: descriptor "vp_i_cb2_48_" (set 3, binding 0, a storage image / texel buffer) used in a draw and never written. The back end logs "not implemented: storage image / texel buffer descriptors" 7000+ times (the game binds images with `nvnCommandBufferBindImages`, 70 per 14 s on the title already). Reading an unwritten descriptor is undefined without robustness; a lost device is the likely result.
- VUID-vkCmdDraw-pStrides-04913: pipeline with dynamic vertex-input binding stride, but the command buffer never bound vertex buffers (vkCmdBindVertexBuffers2 missing for draws without vertex buffers).
- VUID-vkCmdDrawIndexed-format-07753: sampler binding 131 "fp_t_tcb_A" needs a FLOAT component type, bound view is R32_UINT (texture format mismatch with the shader's declared type).
- VUID-vkCmdDraw(Indexed)-imageLayout-00344: image sampled in SHADER_READ_ONLY_OPTIMAL while its tracked layout differs (layout tracking).
- Undefined-Value-ShaderFragmentOutputMismatch-DynamicRendering: fragment output FLOAT into an integer colour attachment.
- WARNING layerCount-compatibility: barrier layerCount 1 for a 3D image.
- VUID-RuntimeSpirv-maxCombinedClipAndCullDistances-00710 on a geometry shader (ClipDistance[14]).
These are S4d's; reproduce with `boot_wt.sh --seconds 100 --env NXRT_GFX_VALIDATION=1 --env "NXRT_BOOT_PRESS=A@12,A@22,A@30,A@38,A@46,A@54,A@62"`.
