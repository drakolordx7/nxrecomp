# S44: glow colour

One optional setting, off by default, so the game looks as it does now:

| Setting | Default | What it does |
|---|---|---|
| `[tweaks] glow_color` | `off` | `R,G,B` (0 to 255 each): the glows of Samus's equipment (suit, morph ball, arm cannon) take this colour. |
| `[tweaks] suit_glow` | `auto` | `auto` follows `glow_color`, `off` keeps the game's colour, `R,G,B` is the suit's own colour. |
| `[tweaks] ball_glow` | `auto` | The same for the morph ball. |
| `[tweaks] gun_glow` | `auto` | The same for the arm cannon (its lit parts and the charge glow). |

The launcher has a Tweaks tab, and so has the F1 page: a switch, three sliders with a colour swatch, a Reset button and a "Per part" choice. The F1 page shows the colour in the game while the sliders move; Apply and save keeps it. Every change applies at once, with no restart. The keys are in `docs/CONFIG.md`.

## Why the first version did not show

The first version recoloured the morph ball's colour tables and gave the ball's inner glow and the charge effect a particle modulation colour. Its screenshots kept the game's colours, because what the eye reads as "the glow" is neither of those:

* The bright white-blue stripes of the morph ball, the orange lit panels of the arm cannon and the suit's lights are the models' incandescence: the materials' `ICAN` glow map times their `ICNC` colour, drawn with the model.
* The colour tables only feed the trail, the boost glow, the ball's light and the morph flash, which are faint or only there while rolling or boosting.

## What changes the colour now

Model incandescence (the main glow). `CModelFlagsMPT` (the flags every model draw takes) has a colour mode for the glow: mode 2, built by `CModelFlagsMPT::ColorModulateIncan(CColor4f const&)` (0xb41578). `CModelFlagsMPT::CreateModelRenderState` (0xb42074) copies a mode-2 colour into the model render state's incandescence modulation (render state +40, flag bit 2). The game uses it for `CScriptColorModulateMP1`. Samus's models are drawn with `Normal` flags (mode 0, white). The tweak hooks the three model draw functions they go through and, for the calls that draw Samus's equipment, passes a copy of the flags in mode 2 with the setting's colour (linear):

| Hook site (new, `recomp/games/mpr/main.sites`) | Flags in |
|---|---|
| 0xfa9694 `CModelDataMP1::Render(CGameRenderCommandState&, CStateManager const&, CTransform4f const&, CModelFlagsMPT const&, SCameraData const*)` | x3 |
| 0xfa6c0c `CModelDataMP1::Render(CGameRenderCommandState&, EWhichModel, ...)` | x4 |
| 0xfa7dd0 `CModelDataMP1::RenderGun(CGameRenderCommandState&, EWhichModel, CTransform4f const&, SGunRenderParams const&, CModelFlagsMPT const&)` | x5 |

The caller is told apart by the return address (x30 at the entry; the lifted code sets it before every call, and the wrapper's tail call keeps it):

* Ball: `CMorphBallMP1::Render` hull 0xcea890 and Spider Ball 0xceade4.
* Gun: `CGunWeaponMP1::Draw` 0xca2594/0xca2638/0xca26d4, `DrawGunWithRain` 0xca2a24, `CPlayerGunMP1::Render` 0xc92a48/0xc92b68.
* Suit: `CPlayerMP1::Render` 0xc72cd8/0xc731e4/0xc7340c/0xc72d9c/0xc72ff8/0xc730a4 and `CSamusDollMP1::Draw` 0xe7b00c.

Only mode 0 and mode 2 flags are changed. Additive, colour-add (the boost glow) and darken draws keep the game's effect. The flags copy is written to the guest stack below the caller's frame, and the draw function runs with sp below it. The render commands copy the flags (`CNormalModelRenderCommandMP1`, `CGunRenderCommandMP1` constructors), so nothing keeps the pointer.

Colour tables. `CMorphBallMP1` has five static tables of linear `CColor4f`, five entries each (glow index 0 Power, 1 Varia, 2 Varia with the Spider Ball, 3 Gravity, 4 Phazon; `CMorphBallMP1 + 0xc` is the index), filled by the module's static init:

* `skBallNormalSwooshColors` 0x4b24a48
* `skBallBoostedSwooshColors` 0x4b24a98 (trail)
* `skBallBoostedHullGlowColors` 0x4b24ae8 (boost glow)
* `skBallLightningSwooshColors` 0x4b24b38
* `skBallLightColors` 0x4b24b88 (light, morph flash, pause screen)

They are rewritten in place at the frame boundary when the wanted colour changes (each entry: the setting's hue at the game's brightest channel, alpha kept). The game's values are written back when the setting goes off.

Particle modulation. The ball's inner glow (`CMorphBallMP1 + 0x2100 + 8 * index`, a `CElementGen` drawn with no modulation colour) and the arm cannon's charge glow get the colour through `CParticleGen::SetModulationColor` (vtable `+184`). It is called on the guest every frame while the setting is on, from the existing `CPlayerMP1::ProcessInput` and `CPlayerGunMP1::Update` hook sites. For the charge glow, `CGunWeaponMP1::DrawMuzzleFx` draws the generator at `CGunWeaponMP1 + 1392 + 16 * stage` while the charge stage at `CGunWeaponMP1 + 1520` is 1 or 2; the weapon is at `CPlayerGunMP1 + 1272`.

## Colour math

The setting is sRGB; incandescence and table colours are linear. The incandescence colour is `linear(setting)` and multiplies the glow map, so a white glow (the ball's stripes) takes the colour exactly and a coloured one mixes with it. The particle glows are multiplied by the setting's sRGB bytes, so the yellow charge times magenta gives red-pink. A darker setting gives a dimmer glow.

## Results

One live run of the Frigate hangar (`glow2_44.py`, headless, muted), with pairs from the same spot and pose: the game's colours, then `glow_color = 255,0,255` switched live through `NXRT_GLOW_TEST_FILE`. The log's per-site counts (`draw sites while on`) show which draws were changed.

| What | Result |
|---|---|
| Morph ball, standing and rolling | Changes. The white-blue stripes turn magenta (model incandescence, site 0xcea890, flags mode 0 to 2). The ball's shell also turns pink. Whether that comes from the incandescence or from the ball's light (`skBallLightColors`, now magenta) was not separated. |
| Arm cannon charge | Changes. The charge ball and its rays go from yellow to pink-red (particle modulation of the charge generator at `CGunWeaponMP1 + 1392 + 16 * stage`). The first version read +1416/+1424 as effect modules, which only matched by chance, so its tint never reached the charge. A yellow particle times magenta is red, so the colour mixes with the game's yellow instead of replacing it: particle modulation is a byte colour and cannot go above the game's own. |
| Arm cannon's lit panels | Not changed (a slight shift: brightest panel pixels 254,235,186 to 255,228,98). Both cannon draws (0xca2638, 0xca26d4, `CModelDataMP1::Render` from `CGunWeaponMP1::Draw`) get mode 2 with magenta every frame, and the panels stay yellow. Their glow is therefore not the incandescence that mode 2 modulates; it is a separate emissive term of the gun's materials, not found yet. |
| Suit | Hooked (the `CPlayerMP1::Render` and `CSamusDollMP1::Draw` draw calls). No visible change in the one third-person view checked (`glow2_suit.py`: Samus from behind, 8 and 16 frames into the morph). The Power Suit shows no lit parts there, and the pictures match. In first person only the arm is seen, and it is part of the cannon's model. |

## Not done

* The arm cannon's own lit panels. Next step: a RenderDoc capture of the cannon draw to see which constant or texture gives the panels their colour (the `SGunRenderParams` colours at `CGunWeaponMP1 + 1652` are used only by `RenderGun`, which these runs never reached), or a texture recolour as S45 (tint) plans for the suit.
* The suit: no glowing part of the Power Suit was found in view. The visor and the other suits (Varia, Gravity, Phazon) were not checked.
* A true colour replacement for the charge (it mixes with the game's yellow).

## Files

* `src/gfx/play/play_tweaks.h` (header-only): `TweakSettings`, the key parsing and formatting. The launcher and the game use the same code.
* `src/gfx/play/play_glow.h`, `play_glow.cpp` (hooks, tables, particles), `play_glow_ui.cpp` (F1 Tweaks tab). They sit next to the other title code of main (`play_lockcam`, `play_scenefix`).
* Shared, small: `play_types.h` (`Settings::tweaks`), `play_config.cpp` (`[tweaks]`), `play_defaults.cpp` (factory file), `play.cpp` (install, settings, frame, ProcessInput), `play_ui.cpp` (the tab), `apps/launcher/page_tweaks.cpp`, `pages.h`, `main.cpp`, `cmake/launcher.cmake`.
* Tests: `tests/launcher/test_tweaks.cpp` (group `launcher_tweaks`: defaults, parse, write, round trip, auto/off, suit, reset, the factory file) and `tests/gfx/test_play_glow.cpp` (group `gfx_play_glow`: the colour math).
* Recompiler: three entry hooks in `recomp/games/mpr/main.sites`, so the game libraries must be relifted.
* In-game checks: `glow2_44.py` (hangar, charge, ball, roll) and `glow2_suit.py` (the suit during the morph). One live run each, headless and muted, through `NXRT_GLOW_TEST_FILE`.
