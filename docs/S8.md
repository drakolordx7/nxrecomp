# S8: play mode

Play mode turns `mpr.exe` into something a person can play: a resizable window, a frame limiter on the presenting thread, controllers, keyboard and mouse, raw mouse aim, and an F1 settings page. Branch `play`. Debug notes 160 to 163.

## Playing

`mpr.exe` opens a window by default. Tests and scripted runs stay headless (`NXRT_GFX_HEADLESS=1`, `[boot] gfx = headless`, or `--headless`). The first start writes `controls.ini` next to the working directory; F1 opens the page that edits it.

| Key | Action |
|---|---|
| Alt+Enter | Borderless fullscreen on and off |
| F1 | Settings page |
| W A S D | Move |
| Mouse | Aim (first person only) |
| Left button | Fire, hold to charge |
| Right button, Q | Lock on |
| Middle button, F | Missile |
| Space | Jump |
| Left Ctrl, C | Morph ball |
| Left Alt | Free look |
| Tab, M | Map |
| Escape | Pause |
| 1 2 3 4 | Power, wave, ice, plasma beam |
| 5 6 7 8 | Combat, scan, thermal, x-ray visor |
| Wheel | Previous and next beam |
| Arrow keys | D-pad |

In menus Return, Space and the left button confirm, Escape, Backspace and the right button go back, Q and E are L and R, and the wheel scrolls. Any controller works at the same time. Xbox, PlayStation and Switch pads are mapped through SDL; by default buttons follow the printed label (Xbox A is Switch A), the settings page can switch that to position. Gyro goes to the game's six-axis sensor and the game's vibration goes to the pad's motors.

The pointer is captured while you play and released in menus, on the pause screen and while the settings page is open. The mouse aims only in the first-person view, not while locked on, not in the morph ball and not in a cutscene. Sensitivity is shown on the Source engine scale (the file stores radians per count), vertical is separate, and both axes can be inverted.

## How it works

Two entry hooks from the lifter's site list do the work (`recomp/games/mpr/main.sites` is unchanged):

* `CGameArchitectureSupport::Update`, once per rendered frame on the guest main thread, which is also the thread that created the window. It pumps SDL, drains the event queue, applies settings changes, polls the pads, decides the context and the pointer capture, and publishes the pad to the hid input source.
* `CPlayerMP1::ProcessInput`, wrapped: the hook turns the mouse counts since the frame boundary into a yaw (the game's own `CActorMP1::SetTransform`), runs the game's function, then writes the pitch into the free-look angle, so the game's level-out code cannot undo it. The first call after a frame boundary takes the counts; later ticks in the same frame get none.

The game draws and presents from a separate render thread. The frame limiter runs there, inside the NVN present. A present-mode change (vsync option) is applied by a pre-frame hook of the limiter on that same thread, and the overlay got a mutex because its events arrive on the main thread and it draws on the render thread.

Source: `src/gfx/play/` (`play.cpp` glue, `play_engine` bindings and triggers, `play_aim` mouse aim, `pad_map` controller mapping, `play_types`/`play_config` settings file, `play_ui` settings page, `play_selftest` window test driver). Public header `include/nxrt/play.h`. Also changed: `platform` (pad poll, sensors, rumble), `frame_limiter` (pre-frame hook), `overlay` (lock, split apply), `services/hid` (vibration sink), `testtools` (the `key`, `keydown`, `keyup` script verbs, and a merge of the live pad into a scripted one when a script presses keys).

Game facts used by the aim, all read off the 1.0.0 disassembly (`gdis.py`): player camera state `+0x4d0` (0 = first person), morph state `+0x4d4`, orbit state `+0x4e0`, free-look pitch `+0x5cc`, camera manager `[[state manager + 0x4e0150] + 0x30]` with the cinematic fields at `+0x8` and `+0x18` and the first-person camera check from `IsInFPCamera`, pitch limit `CTweakPlayerMP1 + 0x138` through `gpTweakPlayer` (main + 0x4b32880), player state `[gpGameState + 0x20]` with the alive bit at byte 0, current beam at `+0x8`, visor at `+0x18`, item counts at `+0x30 + 8 * item`.

## Settings file

`controls.ini`, documented at the top of `src/gfx/play/play_types.h`: `[mouse]`, `[pad]`, `[timing]`, `[display]`, `[switch]` (what each action presses on the Switch pad), and `[bindings.<context>]` with `input = action [trigger [ms]]`. Contexts are all, gameplay, morph, map, menu, scan; a binding in a context beats the `all` layer, and `none` switches an input off. Triggers are press, tap, hold, toggle, doubletap. `[play]` keys of `nxrt.ini` are in `docs/CONFIG.md`.

Frame limiter: see the gaps. The unit groups `gfx_limiter` and `gfx_pacing` (S4b) hold 60, 120 and 240; in the real game the frames that wait start within 0.1 ms of their schedule (late p99 0.043 to 0.104 ms), but the game itself delivers only about 50 fps at the title screen in window mode, with stalls of 100 to 250 ms, so 120 and 144 fps cannot be shown end to end yet.

## Decisions

* Window mode is the default for a normal launch; `boot.py` sets `NXRT_BOOT_GFX=headless` so the automated boot loop is unchanged.
* The default Switch layout (ZR fire, ZL lock on, R missile, B jump, Y morph ball, plus map, minus pause, X plus d-pad picks a beam, d-pad alone picks a visor) comes from the GameCube port's Remastered preset. It is not checked against the running game and it is one table in the settings file.
* Mouse buttons in menus: with `menu_touch` on, the left click is a touch on the 1280x720 touch screen and drives no binding.
* Closing the window ends the process with `TerminateProcess(0)` after the log and settings are flushed; the game's threads are not unwound.
* No vsync is the default (immediate present with the frame cap), the vsync option switches to fifo.
* Pitch limit is the tweak value (50 degrees if the tweak is in degrees); `[play] pitch_limit_deg` overrides it.

## Gaps

* Gameplay is not reachable yet (S4e), so the aim gate, the context detection (`ProcessInput` calls = in game), the Switch layout and the beam and visor combinations have only run against fakes. Expect to correct them on the first real run. `tools/test/scripts/play_mouse_gameplay.nxs` and `play_check.py mouse` are ready for that run.
* Map and scan contexts are guesses: map is "the map key was pressed and the game stopped calling ProcessInput", scan is "the active visor is scan".
* Free look (Alt) only presses a stick click; the mouse does not turn the view without turning the body.
* Mouse look in the morph ball and a separate morph sensitivity are not done.
* The aim is applied per tick, at most once per rendered frame; at frames above 60 the view still steps at the game's tick rate until the camera-level late sample (hook candidate 4 in `docs/mpr/hooks.md`) exists.
* No pad with a gyro or rumble motor was available; both are tested with SDL virtual devices only. The gyro axis mapping is the one smo-recomp uses.
* Exclusive fullscreen is implemented and not exercised (it changes the display mode).
* Deterministic scripted runs froze once in 12 (frame 128, a guest wait, before any input); see debug note 162.
