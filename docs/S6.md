# S6 stream log: first boot integration

Stream S6 of the Metroid Prime Remastered recompilation: port the runtime to the lifter's ABI 3, build `mpr.exe` (runtime + the four lifted game libraries), boot it and push as far as it goes. Dump: v1.0.0, SDK 12.3.1. Numbered bug notes: `docs/debug/070.md` and up.

## Result (2026-10-21)

- Runtime main: ABI 3 port, NSO loader, 55 of 55 CTest entries pass (54 old + the new `eh_abi3` group, 6 cases).
- `mpr.exe` builds (`game-build/`, the game libraries are imported from `work/build/mpr`) and boots through the game's own startup. It stops at the first Horizon service the game needs.
- Real path (no probe): rtld -> `nn::init::Start` -> `nnosInitialize`, `_init_libc*` -> `nninitInitializeSdkModule` -> `nn::lm::Initialize` -> service `lm` command 0 answered by the stub -> `nn::diag::detail::Abort` -> svcBreak.
- Probe path (`[boot] probe = no-sdk-services`, skips only `nninitInitializeSdkModule`): `nninitStartup` (main: heap search, allocator), `_init_libc2`, every module's constructors (1445 + 112 + 44 init-array entries, run by rtld), **`nnMain` and `COsContext::COsContext()`**, `nn::oe::Initialize` -> `nn::am::InitializeApplicationInterfaces` -> service `appletOE` command 0 (stub) -> Abort. 60 SVC calls, 8 distinct, none unknown; no NVN call yet.

## Build and run

    recomp\scripts\build_mpr.cmd                      the four game libraries (work\build\mpr), ~2 min, only when the lifter or the NSOs changed
    pwsh game-build\scripts\build.ps1                 mpr.exe -> game-build\build\release (runtime sources compile in; first build ~4 min with SDL, then seconds)
    tools\.venv\Scripts\python tools\boot\boot.py     rebuild what changed, run in work\run with a timeout, print stop reason, unknown SVC/IPC/NVN/HLE calls, last lines
    mpr.exe [--exefs DIR] [--ini FILE] [--log FILE] [--max-seconds N] [--link rtld|host] [--no-nvn]     (exefs default: game\exefs baked at configure time, or MPR_EXEFS)

`boot.py` options: `--libs` (also rebuild the game libraries), `--probe no-sdk-services`, `--stub-result 0`, `--link host`, `--env K=V`, `--grep RE`, `--level debug|trace`, `--log-only`. Guest addresses in the report are named from the .dynsym of `work\elf\*.elf` (`tools\boot\addrname.py`). Other helpers: `nso_info.py` (NSO header, disassembly of a module range), `nso_tpidr.py` (TPIDR/TPIDRRO sites), `svc_sites.py` (SVC numbers each NSO uses and which have no handler).

## How the process is started (what the console's kernel and loader do)

1. Map the four NSOs at the bases the lifter baked in (rtld 0x7700000000, main 0x7100000000, sdk 0x7500000000, subsdk0 0x7600000000): LZ4-decompress text / rodata / data, bss after data, MOD0 -> dynamic section. `src/loader/nso.cpp` builds a synthetic ELF image and the ELF loader maps it.
2. Register the lifted tables. Each library exports `nxmod_<name>_abi`; the loader passes it to `nxmodule_register`, so a stale library is refused.
3. Page protections and svcQueryMemory state records only (`module_protect_all`). **Relocation is left to the game's rtld**, as on the console (debug note 071).
4. The host main thread becomes the guest main thread (kernel region stack, 1 MiB as the npdm says; TLS 0x1000 bytes in TPIDRRO_EL0, zeroed except the runtime's own +0x1F0 entry; the SDK keeps its thread pointer at +0x1F8 and sets it itself in `nnosInitialize`). The host stack is 128 MiB (`/STACK`) because lifted code nests on the host stack.
5. Enter rtld offset 0 with x0 = 0 and x1 = the main thread handle. rtld: self-relocation (0x13c0), dynamic linker (0x4b0: finds the other modules with svcQueryMemory, relocates, registers module objects), then `nn::init::Start(handle, exception handler, 0x138c, 0x820, 0x870)`.
6. `Start` order (from its disassembly): `_init_libc0`, `nnosInitialize(handle, handler)`, rtld+0x138c, `_init_libc1`, `nninitInitializeSdkModule`, `nninitStartup` (main), `_init_libc2`, rtld+0x820 (every module's DT_INIT: constructors), `nnMain` (main), rtld+0x870 (finalizers), `nninitFinalizeSdkModule`, `nnosQuickExit`. So init order is the game's, not ours.

The first 0xd8 bytes of rtld and the function at rtld+0x138c are not in the lifted table (lifter gap, debug note 070); `mpr_main.cpp` stands in for them instruction by instruction.

## Decisions not in the brief

- `game-build/` in the root repository is the game project (CMake `add_subdirectory(../runtime)`, imported static libraries). Nothing game-derived is in it; the NSOs are read at run time.
- Default link mode is `rtld` (debug note 071); `host` stays as a cross-check and reaches the same stop point.
- SetHeapSize now enforces the advertised memory (debug note 072); `GetInfo(UsedMemorySize)` counts the images. CNTPCT_EL0 / CNTVCT_EL0 / CNTFRQ_EL0 are real (note 073).
- `[ipc] stub_result` (bring-up probe) and the raw argument bytes in the stub-service log line, so the services stream sees the command payloads. `svcExitProcess` and `svcBreak` log the end-of-run summary first.
- ABI 3 runtime semantics: `DynSym.value` used as is; `NxEh.type_syms` resolved by name through the module registry when the slot is 0 (cached; an import no module defines matches nothing and is logged once); exception specifications: a thrown type not in the list lands at the call site's pad with the (negative) filter as selector, the guest then calls `__cxa_call_unexpected` / terminate. The game has 13 empty `throw()` specifications in `sdk` and no typed catch, so the symbol path is exercised by the unit tests (`eh_abi3`) only.

## Lifter findings (for the lead; `recomp/` was not touched)

1. rtld has no lifted function at offset 0 (the process entry) and none at 0x138c. `recomp/games/mpr/config.py` `extra_entries = {'rtld': [0x0, 0x138c]}` should add both (debug note 070). The host stand-ins in `mpr_main.cpp` only run when the lifted table lacks them.
2. No other discovery gap has shown up in the 138,504 lifted functions that ran so far (1445 + 112 + 44 constructors, the allocator start-up, the SDK start-up).

## Gaps

- The boot has not gone past service initialisation: everything beyond blocker 2 is unseen (threads created by the SDK, fs/RomFS, NVN, audio, hid).
- The runtime's linker (`module_link_all`) is no longer on the boot path by default; it stays covered by the loader tests and the `--link host` cross-check. Memory images after the two linkers were not diffed.
- `rtld`'s exception entry (x0 != 0, `br` to the user exception handler) is not implemented (traps if reached). The SDK installs its handler through `nnosInitialize`; nothing raised an exception yet.
- Guest-provided services (CreatePort / ReplyAndReceive) are not implemented (README gap, unchanged).
