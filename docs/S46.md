# S46: skip the opening cutscene, faster menus

Branch `fastboot`. Three options in a new `[tweaks]` section of `controls.ini`, all off by default, so the game plays as it does now:

| Setting | Default | What it does |
|---|---|---|
| `skip_intro` | `0` | `1`: New Game skips the opening cutscene (the gunship flying to and landing on the Frigate Orpheon) without a key press, through the game's own cutscene skip. |
| `skip_boot_logos` | `0` | `1`: the title's 14 s intro movie (the logo forming) is ended as soon as it plays; the title screen comes up at once. |
| `fast_menus`, `menu_speed` | `0`, `2` | `fast_menus = 1`: the front end runs its clock `menu_speed` (1 to 4) times faster: animations, fades, waits. |

They are on the F1 page (Extras tab, "Start-up and menus") and the launcher's Extras tab, and described in `docs/CONFIG.md`.

The first brief also asked to skip the boot logos. The Switch version has no Nintendo or Retro logo cards and no health or legal screen before the title: the first thing on screen is the 14.1 s movie `45d4dd7e-45af-40f6-b6ed-8b76c33c90fb` (black, the logo forms, then the loop `6278ecfd-...` with "press start" takes over; frames checked with ffmpeg from `work/media_fmv`). So `skip_boot_logos` skips that movie. The user then changed `skip_intro` to mean the landing cutscene.

## What the game does

### Cutscene skips

The Remastered has two skip paths, both read the "skip" command (command 1) with `CCommandFrame::GetDigitalPressedInput`:

* Legacy cinematics (`CCinematicCameraMP1`, the Prime 1 scripts). `CGameIOWinMP1::UserInput` counts the time a cinematic camera has been current. After 2 s, if the area registered a skip object (`CStateManagerGameLogicMP1 +2932`) and the skip command is pressed, it goes to state 3: fade out. `CGameIOWinMP1::TimerTick` state 3 waits 1 s and calls `CStateManagerGameLogicMP1::SpecialSkipCinematic`: if `CScriptSpecialFunctionMP1::CanSkipCinematic`, it stops the cinematics and `SkipCinematic` sends the special function's script messages. That is the level designers' jump to the end state (Samus placed, camera, music, layers), the same path a manual skip takes.
* The skip object is a `CScriptSpecialFunctionMP1` of type `CinematicSkip` (0xF). When the cutscene starts (message 7) it registers itself only if `CGameState::IsCinematicSkippable(its GUID)` is true (seen before, or `mCinematicForceSkippableOverride`) or Metroid Prime is beaten. When the cutscene ends (message 5) it marks the GUID skippable for next time.
* Newer cinematics (`CCinematicCamera`, `CCameraManager::CheckForCinematicSkip`) gate on the camera's own "skippable" and "skippable once seen" flags (`CUniverseState::HasViewedCinematic`, production flag `gCinemaSkipIgnorePreviouslySeenFlag`), then a press either queues the skip handler's messages or requests the skip with a fade (`CCameraManager::UpdateCinematicSkip`).

The practice mod (`refs/mp1r-practice-mod`, "Allow skipping all cutscenes") and the randomizer (`refs/MP1R-Rando-CodeEdits`) set `CGameState::mCinematicForceSkippableOverride = true`, which makes every legacy cutscene skippable by a press. Nothing in them skips without a press.

### The front end

The title, main menu, save slots and options are a script-driven area run by its own `CStateManager` (`CFrontEndIOWin`, components `CFrontEndManagerGOC`, `CUIMenuGOC`, `CTimerGOC`, `CStreamedMovieGOC`). `CFrontEndIOWin::TimerTick` updates it through `CStateManagerIOWin::TimerTick` -> `NIOWinStateManagerUtils::UpdateStateManager` (`CStateManager::Update(parm.dt)`). Every timer, UI animation and fade of the front end is driven by that step. Movies have their own clock (`CMovieList::Update`).

`CStreamedMovieGOC` (props at `+56`, FMV id at `+128`, CMovieIOWin handle at `+160`, skip state at `+144`) has `Skip(CStateManager&, bool immediate)`: state 4 makes the next `Think` call `CMovieIOWin::Skip`, unload and send the movie's end messages.

## What the options do

`games/mpr/mpr_fastboot.cpp`, five entry hooks (recomp `games/mpr/main.sites`, "S46" block):

| Site | Function | Use |
|---|---|---|
| 0x4d71f0 | `CCommandFrame::GetDigitalPressedInput` | `skip_intro`: answers "pressed" when called from the two skip sites (return address 0xe51e78 in `CGameIOWinMP1::UserInput`, 0x4bd840 in `CCameraManager::CheckForCinematicSkip`) while the current area is the Exterior Docking Hangar (world `4b5e8635-...`, area `a8444ff6-...`). Any other caller is untouched. |
| 0x40a2dc | `CGameState::IsCinematicSkippable` | `skip_intro`: true in that area, so the cutscene's skip object registers itself (what the override does everywhere). |
| 0x852b28 | `CStreamedMovieGOC::Think` | `skip_boot_logos`: for movie `45d4dd7e-...`, once it plays, `Skip(immediate)`. Also logs every streamed movie id once. |
| 0x41a21c | `CFrontEndIOWin::TimerTick` | `fast_menus`: marks the front end's tick (thread-local), and rearms `skip_intro` for the next new game. |
| 0x41b000 | `NIOWinStateManagerUtils::UpdateStateManager` | `fast_menus`: inside that tick, the step at `parm + 8` is multiplied by `menu_speed` (capped at 0.1 s) for the call and put back after, so the same message reaches other windows unchanged. |

`skip_intro` stays on for 10 s after its first press, so a chain of cutscenes in the opening is skipped too, and is then off until the front end runs again while the game's current area is not the hangar (the title after boot, or after quitting from elsewhere): a later cutscene in the hangar (a scan, a door) plays as usual. Quitting to the title from the hangar itself and starting another new game in the same session does not rearm it (the area still reads as the hangar there). The player still sees about 2 s of the cutscene and a 1 s fade, because the game accepts a skip only after 2 s.

Without the new lift the hooks never fire and the options do nothing.

## Checks

Unit and hook tests (no game): `pwsh fastboot_tests.ps1 -Filter "play_fastboot|play_config|launcher"`. Groups `play_fastboot` (the keys: defaults off, read, write, bad values, unknown keys of other tweaks) and `play_fastboot_hooks` (the hooks driven through `nx_hook_entry` against stand-in guest functions: the press only at the two skip sites and only in the hangar, the skippable answer, the front-end step scaled and restored and capped, the intro movie skipped once and no other movie).

In the game (GPU window): `python fastboot_time.py TAG [--intro 1] [--logos 1] [--fast 1 --speed N]` runs one live session (window, muted): boot to title loop (game log), title to New Game (mashing A every 20 frames until the game clock runs), New Game to first control in the hangar (gameplay camera for 2 s of game time); it keeps the hangar state at first control and 10 s later and screenshots in `work/shots_wip/fastboot_TAG_*`. `--compare TAG_A TAG_B` prints the timings and the state side by side.

Build: `build_mpr_fastboot.cmd` (lift with the new sites into `work\build_fastboot`), `pwsh fastboot_game.ps1` (mpr.exe and the launcher into `game-build-fastboot`).

power beam, combat visor, gameplay camera; 10 s later the same again (the heading differs only because the `look` helper turned the view).
Screenshots `work/shots_wip/fastboot_hangar_off_vs_on.jpg` (top: first control, HUD fading in on both; bottom: 10 s later), and
`fastboot_{off,on}_*`.

What the first "on" run showed: the opening's skip object (`2ac311c5-55aa-40a6-802b-2177deaae976`) asks `IsCinematicSkippable` while the area
loads, when the world state's current area is still zero. The area test alone missed it and the cutscene played in full. The object is now
matched by its GUID; the press then comes through the legacy path (`CGameIOWinMP1::UserInput`), as expected.

The front end: after "press start" the game plays an 8 s transition movie (into the cells) before the main menu appears, and two more around
the menu backgrounds. Scaling the front end's clock does not touch movies, so `fast_menus` now also cuts those three transition movies after
1/menu_speed of their length (their own `Skip(immediate)`; the menus wait for their end messages).

## Decisions

* The opening is skipped through the game's own skip (a synthetic press at the two places that read it, plus the "skippable" answer the override gives), not by patching area scripts or warping. The end state is then whatever the level designers wrote for a skip.
* The area test (Exterior Docking Hangar) plus a 10 s window decide what "the opening" is. The cutscene's own GUID will be logged by the first run (`fastboot` log lines) and can pin it further.
* Menus are sped up by the front end's time step, one mechanism for every fade, animation and wait, with a speed setting (1 to 4). Input handling stays the game's, so pad, keyboard and mouse work the same; at 4x the menu animations are short but nothing is skipped.
* `skip_boot_logos` stays as a separate toggle because it was cheap: one movie, its own skip.
* The keys live in their own struct and file (`play_fastboot.*`); the shared tables got one section (`[tweaks]`) and one call each.
