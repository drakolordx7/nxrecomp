# S33: the first release candidate

Branch `rc` in the root, runtime and tools repositories. This round prepared version 0.1.0: a version number everywhere, a clean install walked through the way a new player does it, the fixes that walk found, the player documents, and the scripts that build, check and package a release. Nothing was pushed or published.

## Version

`game-build/scripts/build.ps1 -Release -Version 0.1.0` (or `-DMPR_VERSION=0.1.0`) stamps one string into four places:

* the launcher shows `v0.1.0` in the top right corner and in its title bar (`apps/launcher/main.cpp`, `cmake/launcher.cmake`);
* `mpr.log` has a line `boot: mpr 0.1.0 (Metroid Prime Remastered PC port)` near the top, and `mpr.exe --version` prints `mpr 0.1.0` (it prints into a terminal, or into a file when the output is redirected);
* the file properties of `mpr.exe` carry the version (`game-build/res/mpr.rc`);
* the setup tool writes `mpr_setup 0.1.0` at the start of every `setup.log` run, shows it in its window title, and `mpr_setup_cli --version` prints it (`tools/setup/scripts/build.ps1 -Version 0.1.0`).

Without a version the strings say `dev`.

## What the clean install found

The release zip was unpacked into `work/rc/clean room Tést/` (a folder name with a space and a non-ASCII letter), with `APPDATA` pointed at `work/rc/Üser Dátà/AppData/Roaming`, and walked through with window messages only (`cleanroom_rc.py`): launcher, "Set up game files...", setup with the real dump and keys, shader preparation, Play, title, New Game.

| Finding | Result |
|---|---|
| `mpr.exe` had no UTF-8 manifest. The launcher always starts it with `--game <folder>`, and the command line, `getenv("APPDATA")` and every narrow file call went through the ANSI code page. A folder with a non-ASCII letter made the old exe stop with "cannot use the game folder" (checked with the S30 build). | Fixed: `game-build/res/mpr.manifest` sets the UTF-8 code page and long path support. The new exe starts from that folder, and its saves go to the non-ASCII profile folder. |
| Two copies of the game could run from one folder and write the same log, pipeline cache and saves. | Fixed: a named mutex per game folder; the second copy shows "The game is already running from this folder" and exits. `NXRT_ALLOW_MULTIPLE=1` lifts it for test rigs. |
| XCI dumps: setup read the root partition address from the header's size field (offset 0x138 instead of 0x130). The tests built their XCI the same wrong way. | Fixed in `container.cpp`; the test XCI now has an address and a different size. A real cartridge dump has still not been tried. |
| Setup window: the two-line "no keys found" message was clipped. | Fixed: the status lines are one line taller. |
| `mpr.exe --version` printed nothing into a redirected file (the console attach replaced the redirect). | Fixed: it only attaches to the parent console when no output handle was given. |
| Setup with bad input (`mpr_setup_cli --check`). | Every case gives a plain message and exit code 2: a missing dump ("Cannot open ... (Windows error 2)"), a text file ("This file is too small to be a Switch game dump"), a truncated dump ("The package is damaged: file ... runs past the end of the package"), a garbage or empty keys file ("does not look like a keys file"), a missing keys file ("Cannot read the keys file"). In the window, no keys at all gives "No Switch keys file was found. Pick your prod.keys file ...". |

Not found to be a problem: spaces in paths (the launcher quotes every path it passes on), uninstalling (nothing is written outside the game folder and `%APPDATA%\MPRRecomp\save`; the clean run left nothing else), a second launcher after the game closed.

## Scripts

* `release.sh <version>`: builds, packages, audits and smoke-tests a release and writes the notes. It never publishes. `release_publish.sh <version>` is the separate publish step.
* `smoke_rc.py`: unpacks the zip, links a finished install's data into it, plays New Game up to the first control (headless, no sound) and checks play time, health, the version line, the log and crash reports.
* `cleanroom_rc.py`: the clean-install walk above.
* `tools/release/make_release.py` now ships `HELP.txt` and writes `<zip>.sha256`.
* `daily.sh`, `inbox.py`, `ghdigest.py`, `forkscan.py`, `credits_check.py`: the GitHub watch tools (read-only).
