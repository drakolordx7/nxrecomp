# 024: texture cache keys equal the runtime's

**Question.** The cache is only useful if the key built from the TXTR on disk equals the key the runtime computes from the texture in game memory (hash of the tiled bytes seeded with format, size, level count, layers, block height, pitch and quality).

**Check.** The runtime had already written 263 `.bc7` files during boot tests (three folders). All 263 file names exist in the cache built by the setup tool and all 263 are byte identical. Quality is part of the key: files built at quality 3 are only found by a runtime whose `[nvn] bc7_quality` is 3, so the tool writes the quality it used into `mpr.ini`.
