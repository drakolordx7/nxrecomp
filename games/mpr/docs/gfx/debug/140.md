# 140 The first gameplay path through the NVN back end: what was wrong and what fixed it

Run: title, menu, New Game, the loading screen, then the world. Before this note the Vulkan device was lost about a minute into the loading screen. Validation messages and fixes, in the order they were found. Each fix has a test (`docs/S4e.md`, "Tests").

| Symptom (validation id or log line) | Cause | Fix |
|---|---|---|
| VUID-vkCmdDraw-None-08114, a storage image descriptor "vp_i_cb2_48_" never written; 7,037 "storage image / texel buffer descriptors" skips | `nvnCommandBufferBindImages` handles (texture pool ids) were never turned into descriptors | storage images: the pool entry's texture as a storage view (GENERAL layout, format from the shader's image format); a 1x1 dummy storage image when the game bound nothing usable |
| VUID-vkCmdDraw-pStrides-04913 | the vertex binding stride is dynamic; a command buffer whose draws had no vertex buffers never called `vkCmdBindVertexBuffers2` | a draw whose pipeline has no vertex bindings binds the dummy buffer once per command buffer |
| VUID-VkGraphicsPipelineCreateInfo-Input-07904 | the vertex shader reads an attribute location the game did not set up (and an input array reads several locations) | every input location (array elements included) gets an attribute; unset ones read (0,0,0,1) from the last 32 bytes of the dummy buffer through a stride-0 binding |
| VUID-RuntimeSpirv-OpEntryPoint-08743 | the fragment shader reads varyings (an indexed array of 16 vec4) that the stage before it never writes | `spirv_add_outputs`: the producer module gets never-written outputs in the missing slots (pipeline-time variant, cached per (module, slots)) |
| VUID-vkCmdDraw(Indexed)-imageLayout-00344 | a depth texture was sampled while it was the depth attachment of the pass; the descriptor said SHADER_READ_ONLY, the pass DEPTH_STENCIL_ATTACHMENT | such a draw runs in a pass whose depth attachment is DEPTH_STENCIL_READ_ONLY_OPTIMAL (depth writes and stencil write mask off); depth textures are always sampled in that layout. A colour attachment sampled in its own pass gets the dummy texture |
| VUID-vkCmdDrawIndexed-format-07753 (sampler wants FLOAT, view is R32_UINT) and Undefined-Value-ShaderFragmentOutputMismatch (float output, R32_UINT attachment) | the translated shaders declare every sampled value and colour output as float; Maxwell moves raw register bits | 32-bit integer colour formats are viewed and rendered through their float alias of the same size (mutable-format images); a sampler view takes the integer or float alias the shader's sampled type asks for |
| WARNING-VkImageSubresourceRange-layerCount-compatibility | layout barriers of a 3D image used layerCount 1 | VK_REMAINING_ARRAY_LAYERS for 3D images |
| VUID-RuntimeSpirv-maxCombinedClipAndCullDistances-00710 (geometry shaders, ClipDistance 14 + CullDistance 2) | validation layer false positive: it adds the gl_in block and the output block; the module declares 7 + 1 each (KhronosGroup/Vulkan-ValidationLayers#13414) | message filtered in the debug callback (geometry stage only) |
| 21,806 "ClearDepthStencil with a partial stencil mask" | `vkCmdClearAttachments` has no stencil write mask, the whole stencil was cleared | a full-screen triangle with stencil op REPLACE, the write mask and the reference as dynamic state, depth test ALWAYS at a constant viewport depth |
| VUID-vkCmdDraw-maxFragmentDualSrcAttachments-09239, Undefined-Value-ShaderOutputNotConsumed | a blend factor reads the second source; the console takes it from render target 1's output, Vulkan from Location 0 / Index 1; fragment outputs written with no attachment | `spirv_dual_source_output` moves the Location 1 output; unused outputs are listed in the pipeline as UNDEFINED attachments (VK_EXT_dynamic_rendering_unused_attachments) |
| VUID-vkCmdDraw-None-07842 | the masked-clear pipelines have no dynamic topology / restart state; binding them invalidates the values the replay had cached | the cached values are dropped after a masked clear |
| nvnMemoryPoolMapVirtual returns 0, black world | the baked lighting probe volumes (six 512x256x368 BC1 / BC6H 3D textures in a virtual pool, sampled by the world vertex shaders) could not be built | the call succeeds (sparse textures are resident dense images; the game fills them with copy commands); `nvnTextureGetSparseTileLayout` returns the standard 64 KiB tile shapes (words 1 to 3 are width, height, depth) |
| two blocks "no translated shader" | the survey missed two fragment shader blocks (f08b77d7b1e306f1, f02593d3213eff99) | translated and added to the cache; `[nvn] dump_missing` writes any block the cache lacks in the corpus layout for the harness |
| World renders black (the forward pass is correct, the final image is not); log line "a storage image binding has no usable texture: a dummy storage image is bound" | the 100x57x64 RGBA16F fog volume is written by a vertex shader through an image binding; the game does not set the texture builder's IMAGE flag, so the image had no storage usage, the binding got the dummy image, the volume stayed zero and the fog composite multiplied the scene by a transmittance of zero | every uncompressed colour image keeps the storage usage when the GPU accepts the combination |
| VUID-vkCmdBeginTransformFeedbackEXT-None-04128, VUID-vkCmdBindPipeline-None-02323 | feedback began before the stream-out pipeline was bound, and a pipeline change happened inside a section | begin after the bind, end before a pipeline change (the counter buffer carries the byte position over) |
| Undefined-Value-ShaderOutputNotConsumed-DynamicRendering in the world | depth-only passes (shadow maps) run the material's fragment shader, which writes a colour output with no attachment | in a pass without colour attachments the fragment shader's outputs become private variables |

The loss of the device itself did not recur once the descriptors, the read-only depth pass and the vertex input fixes were in; the last timeline-semaphore messages in the old log (`VUID-VkSemaphoreSignalInfo-value-03259`) were a consequence of the loss.

How the black world was found: the trace tools of S4e (`NXRT_NVN_TRACE_SNAP_FS`, `NXRT_NVN_TRACE_SNAP_SAMPLED`) copy the targets and the sampled textures after chosen draws. The forward pass was correct; the first draw that turned the target black was the fog composite, whose sampled volume was all zero; the draw before it writes the volume and its binding went to the dummy image.
