# 442 Objects missing where a vertex shader indexes its attributes: the integer-attribute patch refused the Input array

Symptom (sweep, S4g): `nvn.pipe: <hash>: the integer vertex attributes could not be patched in; draws with this shader are skipped` for eight vertex shaders (ef17e15bcbcfaa67, c439de15f8c11afe, 703a0d4c57b5b6cd, b463900441176f0d, ae70171833c0aa23, b89994b88d0c4ca6, d935dfe04438f85f, 3fd16328fc86931e). Draws with them were dropped, so the objects they draw were missing: the glowing orange stripes on the gunship's engine casings in the opening cutscene (Eden has them), and objects in chozo_antechamber and other rooms.

Cause: all eight declare one Input variable, an array of 16 vec4 at Location 0, because the game indexes its attributes with a computed value. `spirv_int_attributes` (S4f, docs/S4f.md) looked for a plain vec4 Input at each integer slot's Location, found none and gave up.

Fix (`nvn_spirv_patch.cpp`): the array variable becomes Private as a whole; every Location it covers gets its own new Input (float, uvec4 or ivec4 by what the draw feeds at that Location); the entry point loads them, bitcasts the integer ones and builds the array with one OpCompositeConstruct. The entry point's interface loses the old variable and gains the new ones. Test `gfx_nvn_spirv_patch.int_attributes_reach_an_indexed_attribute_array` (spirv-val, input types by Location, refusal outside the array).
