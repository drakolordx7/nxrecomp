# S41: static analysis of the runtime

Branch `pvs`, from main `e86ec39`. Scope: `src/` and `apps/` (there is no `games/` folder on main yet; the boundary refactor that adds it is still on its own branch). Third-party code, `_deps` and `tests/` were left out.

## Tools run

- PVS-Studio 8.01, `CompilerCommandsAnalyzer.exe analyze` on a `compile_commands.json` filtered to the 168 project translation units, modes `GA;64`, 4 jobs, about 10 minutes. 2,126 warnings in project files.
- clang-tidy 23.1.4 with `bugprone-*`, `concurrency-*` and `clang-analyzer-*` (core, cplusplus, unix, deadcode), minus the checks that only flag style (easily-swappable-parameters, narrowing-conversions, implicit-widening, reserved-identifier, macro-parentheses, switch-missing-default, exception-escape, concurrency-mt-unsafe and a few more). It has to run inside `scripts\env.cmd`, or it cannot find the MSVC headers. 1,155 warnings, header warnings counted once per translation unit.
- A short read by hand of the memory and synchronisation SVCs near the PVS hits there. Two of the four bugs below came from that read, not from a tool.

Build folder: `work\build_pvs` (Release, clang-cl, /MT, `CMAKE_EXPORT_COMPILE_COMMANDS=ON`, offline deps from `runtime\build\release\_deps`). The PVS log is `work\build_pvs\pvs.plog`, the flat list is `pvs_list.txt`, and the clang-tidy output is `tidy.txt`.

## Dismissed

Out of 2,126 PVS warnings:

- 1,625 are from the 64-bit rule set (V1xx/V2xx: memsize types, magic numbers, implicit casts). They are noise for an x64-only build. A spot check of V127, V221 and V1028 found only deliberate casts and counters that cannot overflow.
- 164 are V1042 (the GPL licence notice), 65 are V550 (exact float compares, all deliberate), 68 are V1091 (pointer-to-integer casts for guest addresses) and 30 are V1048 (a field set to the value it already had).
- 171 general-analysis warnings were read one by one, and all but the two above are false positives:
  - V1086 memcpy "underflow" (8): partial copies on purpose (NVN builder headers, register saves, guest structs).
  - V522 and V1004 null dereference (17): the pointers are checked by validation or are always set after init (`st.engine` in play.cpp is created in init and never reset).
  - V547 and V560 always-true or always-false (25): PVS losing track of state across a lock or a loop (movie_mf, vk_device GPU pick, hid, vi_nv vsync), or redundant guards.
  - V1037, V524 and V525 identical branches (30): enum and format tables where different inputs really do map to the same value.
  - V1051 misprint (5): ring-buffer and timestep code is correct.
  - V581 identical `if` (4): two statements guarded by the same condition.
  - V1020 missing unlock (4): unlock/lock pairs around work, or a return from a scoped lock.
  - V1089 wait without a predicate (12): every one sits in a loop that checks its condition again.
  - V576 format (6): `%d` given an unsigned value or the other way round, harmless.
  - V506 `node` pointer stored outside its scope (2): the cond-var waiter unlinks itself before it returns.
  - V774 `p` used after free (1): it is only printed, and the file belongs to gpuperf.
  - V1082, V776, V779 noreturn and unreachable code (10): functions ending in TerminateProcess with a `for(;;)` guard.
  - V557 array overrun (1): the loop stops at the NUL.
  - V658 unsigned subtract in the HIPC parser (1): `pos <= nwords` holds throughout.
  - Others (V513, V720, V730, V773, V566, V572, V575, V584, V590, V614, V616, V654, V657, V768, V1001, V519, V1044, V1071, V1073): style or deliberate.

clang-tidy (1,155):

- 1,064 are signed-bitwise, invalid-enum-default-initialization, unchecked-string-to-number-conversion and unhandled-code-paths. All are style.
- 40 branch-clone: the same tables as the PVS V1037 hits.
- 16 misplaced-widening-cast: a hex digit cast to uint64 cannot overflow, and the audren sizes are small.
- 7 not-null-terminated-result: fixed-width Horizon string fields that are not terminated on hardware either.
- 3 raw-memory-call-on-non-trivial-type: deliberate memsets that zero key padding before hashing.
- 9 nondeterministic-pointer-iteration-order: logging order only.
- 2 suspicious-memory-comparison: `GraphicsKey` has 7 bytes of tail padding, and the draw path memsets it, so the comparison holds. It is fragile; see the follow-ups.
- 2 sizeof-expression and 2 incorrect-roundings: `sizeof` of a pointer that is meant (the NVN builder stores a device pointer), and +0.5 rounding of values that are never negative.
- 1 unchecked-optional-access in `hid.cpp:147`: guarded by `shm_ready`.
- 6 clang-analyzer unix.Stream: an `fread` loop after EOF, harmless.
- 1 clang-analyzer null call in `nvn_gpu.cpp:110`: in a gpuperf file, so it was left alone.
- 2 more (bugprone-use-after-move and clang-analyzer cplusplus.Move): the use-after-move fixed above.

## Not done / follow-ups

- `GraphicsKey` (`nvn_pipeline.h`) grew past its explicit `pad[1]`: the struct is now 305 bytes of fields in 312 bytes. `operator==` and `hash()` read the tail padding. Every key that is compared today is built with a memset first, or copied from one. A `static_assert(std::has_unique_object_representations_v<GraphicsKey>)` with a resized `pad` would make this safe for good. It was not changed here because the prewarm record size (`kRestBytes`) depends on it and old `prewarm` files would be refused.
- `nvn_gpl.cpp` `get_part` holds a reference to a `g_libs` entry across a condition-variable wait, and `gpl_shutdown` clears `g_libs`. This is safe only because the render thread is the one that shuts down. Not changed.
- No game run and no `gfx_*` or `extras_output` tests (the GPU was reserved). The one new case in `gfx_nvn_shaders` was run alone and touches no GPU.
