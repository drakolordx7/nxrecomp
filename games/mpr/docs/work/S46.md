# S46: skip the opening cutscene, faster menus

Three options in a new `[tweaks]` section of `controls.ini`, all off by default, so the game plays as it does now. The game hooks are in `games/mpr/mpr_fastboot.cpp`, compiled into `nxrt_gfx` and installed by play mode next to the other hooks.

| Setting | Default | What it does |
|---|---|---|
| `skip_intro` | `0` | `1`: New Game skips the opening cutscene (the gunship flying to and landing on the Frigate Orpheon) without a key press, through the game's own cutscene skip. |
| `skip_boot_logos` | `0` | `1`: the title's 14 s intro movie (the logo forming) is ended as soon as it plays; the title screen comes up at once. |
| `fast_menus`, `menu_speed` | `0`, `2` | `fast_menus = 1`: the front end runs its clock `menu_speed` (1 to 4) times faster: animations, fades, waits. |

They are on the F1 page (Extras tab, "Start-up and menus") and the launcher's Extras tab, and described in `docs/CONFIG.md`.

The Switch version has no Nintendo or Retro logo cards and no health or legal screen before the title. The first thing on screen is the 14.1 s movie `45d4dd7e-45af-40f6-b6ed-8b76c33c90fb` (black, the logo forms, then the loop `6278ecfd-...` with "press start" takes over; checked frame by frame with ffmpeg). So `skip_boot_logos` skips that movie. `skip_intro` skips the landing cutscene.

## What the game does

### Cutscene skips

The Remastered has two skip paths. Both read the "skip" command (command 1) with `CCommandFrame::GetDigitalPressedInput`:

* Legacy cinematics (`CCinematicCameraMP1`, the Prime 1 scripts). `CGameIOWinMP1::UserInput` counts the time a cinematic camera has been current. After 2 s, if the area registered a skip object (`CStateManagerGameLogicMP1 +2932`) and the skip command is pressed, it goes to state 3: fade out. `CGameIOWinMP1::TimerTick` state 3 waits 1 s and calls `CStateManagerGameLogicMP1::SpecialSkipCinematic`. If `CScriptSpecialFunctionMP1::CanSkipCinematic` allows it, that stops the cinematics, and `SkipCinematic` sends the special function's script messages. That is the level designers' jump to the end state (Samus placed, camera, music, layers), the same path a manual skip takes.
* The skip object is a `CScriptSpecialFunctionMP1` of type `CinematicSkip` (0xF). When the cutscene starts (message 7) it registers itself only if `CGameState::IsCinematicSkippable(its GUID)` is true (seen before, or `mCinematicForceSkippableOverride`) or Metroid Prime is beaten. When the cutscene ends (message 5) it marks the GUID skippable for next time.
* Newer cinematics (`CCinematicCamera`, `CCameraManager::CheckForCinematicSkip`) check the camera's own "skippable" and "skippable once seen" flags (`CUniverseState::HasViewedCinematic`, production flag `gCinemaSkipIgnorePreviouslySeenFlag`). A press then either queues the skip handler's messages or requests the skip with a fade (`CCameraManager::UpdateCinematicSkip`).

The practice mod ("Allow skipping all cutscenes") and the randomizer set `CGameState::mCinematicForceSkippableOverride = true`, which makes every legacy cutscene skippable by a press. Neither skips without a press.

### The front end

The title, main menu, save slots and options are a script-driven area run by its own `CStateManager` (`CFrontEndIOWin`, components `CFrontEndManagerGOC`, `CUIMenuGOC`, `CTimerGOC`, `CStreamedMovieGOC`). `CFrontEndIOWin::TimerTick` updates it through `CStateManagerIOWin::TimerTick` -> `NIOWinStateManagerUtils::UpdateStateManager` (`CStateManager::Update(parm.dt)`). Every timer, UI animation and fade of the front end is driven by that step. Movies have their own clock (`CMovieList::Update`).

`CStreamedMovieGOC` (props at `+56`, FMV id at `+128`, CMovieIOWin handle at `+160`, skip state at `+144`) has `Skip(CStateManager&, bool immediate)`. State 4 makes the next `Think` call `CMovieIOWin::Skip`, unload the movie and send its end messages.

## What the options do

`games/mpr/mpr_fastboot.cpp` has five entry hooks (recomp `games/mpr/main.sites`, "S46" block):

| Site | Function | Use |
|---|---|---|
| 0x4d71f0 | `CCommandFrame::GetDigitalPressedInput` | `skip_intro`: answers "pressed" when called from the two skip sites (return address 0xe51e78 in `CGameIOWinMP1::UserInput`, 0x4bd840 in `CCameraManager::CheckForCinematicSkip`) while the current area is the Exterior Docking Hangar (world `4b5e8635-...`, area `a8444ff6-...`). Any other caller is untouched. |
| 0x40a2dc | `CGameState::IsCinematicSkippable` | `skip_intro`: true in that area, so the cutscene's skip object registers itself (what the override does everywhere). |
| 0x852b28 | `CStreamedMovieGOC::Think` | `skip_boot_logos`: for movie `45d4dd7e-...`, once it plays, `Skip(immediate)`. Also logs every streamed movie id once. |
| 0x41a21c | `CFrontEndIOWin::TimerTick` | `fast_menus`: marks the front end's tick (thread-local), and rearms `skip_intro` for the next new game. |
| 0x41b000 | `NIOWinStateManagerUtils::UpdateStateManager` | `fast_menus`: inside that tick, the step at `parm + 8` is multiplied by `menu_speed` (capped at 0.1 s) for the call and put back after, so the same message reaches other windows unchanged. |

`skip_intro` stays on for 10 s after its first press, so a chain of cutscenes in the opening is skipped too. It is then off until the front end runs again while the game's current area is not the hangar (the title after boot, or after quitting from elsewhere). A later cutscene in the hangar (a scan, a door) plays as usual. Quitting to the title from the hangar itself and starting another new game in the same session does not rearm it, because the area still reads as the hangar there. The player still sees about 2 s of the cutscene and a 1 s fade, because the game accepts a skip only after 2 s.

Without the new lift the hooks never fire and the options do nothing.

## Checks

Unit and hook tests (no game), filtered to `play_fastboot|play_config|launcher`. Group `play_fastboot` covers the keys: defaults off, read, write, bad values, unknown keys of other tweaks. Group `play_fastboot_hooks` drives the hooks through `nx_hook_entry` against stand-in guest functions: the press only at the two skip sites and only in the hangar, the skippable answer, the front-end step scaled, restored and capped, the intro movie skipped once and no other movie.

In the game (GPU window): `fastboot_time.py TAG [--intro 1] [--logos 1] [--fast 1 --speed N]` runs one live session (window, muted). It times the boot to the title loop (from the game log), title to New Game (A pressed every 20 frames until the game clock runs), and New Game to first control in the hangar (gameplay camera for 2 s of game time). It keeps the hangar state at first control and 10 s later, and takes screenshots. `--compare TAG_A TAG_B` prints the timings and the state side by side.

## Results

Window runs at 1280x720, null audio, one game at a time but with other projects' games on the same GPU, so the times are indicative only:

| | off (vanilla) | on (`skip_intro`, `skip_boot_logos`, `fast_menus` 3x) |
|---|---|---|
| Boot to title screen | about 19.8 s if left alone (intro movie opens at 5.6 s, length 14.1 s; computed, not timed: the script's A presses ended it early) | 3.9 s (intro skipped as it starts) |
| Title to New Game (A every 20 frames) | 34.0 s | 24.1 s (31.7 s before the transition movies were cut) |
| New Game to first control | 112.7 s | 2.3 s |
| Total, boot to first control | 152.6 s | 30.3 s |
| Play time at first control | 110.8 s | 5.2 s |

Hangar state at first control, off against on: same area, position (91.382, 0.25, -105.227), heading -3.1208, pitch 0, health 99, 15 missiles, power beam, combat visor, gameplay camera. 10 s later it is the same again (the heading differs only because the `look` helper turned the view). Screenshots of both runs show the HUD fading in on both.

The first "on" run showed that the opening's skip object (`2ac311c5-55aa-40a6-802b-2177deaae976`) asks `IsCinematicSkippable` while the area loads, when the world state's current area is still zero. The area test alone missed it and the cutscene played in full. The object is now matched by its GUID. The press then comes through the legacy path (`CGameIOWinMP1::UserInput`), as expected.

The front end: after "press start" the game plays an 8 s transition movie (into the cells) before the main menu appears. Going into Extras and back plays two more (4.0 s and 3.7 s, `c9175984`, `a7aa0bf1`; the Extras background `1a3c8b77` is a loop and is left alone). Scaling the front end's clock does not touch movies, so `fast_menus` also cuts the transition movies after 1/`menu_speed` of their length (their own `Skip(immediate)`; the menus wait for their end messages). The menu walk found that the first version timed only one movie at a time. With two transition movies thinking in the same frames, the timer restarted every frame and neither was cut (the Extras pair at 3x). The timing is now kept per movie object (test `fast_menus_times_each_movie_object_on_its_own`, which fails on the old code). Two table entries were not seen playing in these runs: `21be26c3` (into the menu background) and `d6816cf4` (Play to save slots). The save slots came up within 2 s anyway.

Menu walk (`fbm.sh SPEED ...`, window 1280x720, pointer drawn): at 3x and at 4x, with the pad, the mouse and the keyboard, through the title, main menu (Play, Options, Extras), Options with Controls, Display (a value changed and back), Sound, Extras and Concept Gallery, save slots and difficulty, and back out of each (B, right click, Escape). Mouse hover, click and right-click back work on every one of those screens. The wheel off a slider moves the selection, as without `fast_menus`. Nothing broke, and the transition cuts logged as expected (at 4x: title to menu after 2.0 of 8.0 s, into Extras after 1.0 of 4.0 s, out after 0.9 of 3.7 s).

## Decisions

* The opening is skipped through the game's own skip (a synthetic press at the two places that read it, plus the "skippable" answer the override gives), not by patching area scripts or warping. The end state is then whatever the level designers wrote for a skip.
* The opening's skip object is matched by its GUID, and otherwise by the area (Exterior Docking Hangar). A 10 s window after the first press bounds it, so later cutscenes of the hangar play.
* S47: the "skippable" answer is now given only to the opening's own skip object (the GUID). Before, any skip object asked inside the 10 s window while the hangar was the current area also got "true"; the area test is kept only for the synthetic press.
* Menus are sped up by the front end's time step, one mechanism for every fade, animation and wait, with a speed setting (1 to 4). Input handling stays the game's, so pad, keyboard and mouse work the same. At 4x the menu animations are short but nothing is skipped.
* `skip_boot_logos` is a separate toggle because it was cheap: one movie, its own skip.
* The keys live in their own struct and file (`play_fastboot.*`). The shared tables got one section (`[tweaks]`) and one call each.

## Gaps

* The skip still shows the game's own 2 s before a skip is allowed plus its 1 s fade (control at play time 5.2 s).
* Quitting to the title from the hangar within the 10 s window and starting another new game in the same session was not tried (the skip rearms when the front end ticks outside the hangar).
* Timings come from runs sharing the GPU with other projects, so they are indicative only.
* `fast_menus` also speeds the attract-mode idle timer and the menus' own key-repeat timing if they are time-based.
* The loading screen between the save slot and the hangar is not part of the front end and keeps its speed.
