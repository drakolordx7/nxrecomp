# 021: RomFS integrity tree: short last block is zero padded

**Symptom.** Hash check of the real RomFS (7.24 GB) failed at the very end ("RomFS data fails its check at about 7.24 GB") although every earlier block matched, and extraction of that region was correct.

**Cause.** Each level of the integrity tree hashes fixed-size blocks; the last block of a level that is not a multiple of the block size is hashed as if it were zero-padded to the full block size. The first implementation hashed only the bytes that exist. The ExeFS (hierarchical SHA-256) hashes had no short block in this dump, so it never showed there.

**Fix.** `Nca::verify_section` retries a short final block zero-padded when the plain hash does not match. Real dump: all levels verify, 7.24 GB in 7.6 s. Synthetic tests still use the plain hash and pass through the first branch.
