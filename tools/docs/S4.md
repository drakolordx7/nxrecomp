# S4 stream log: graphics offline tooling

Three tools in this repo, each with a README, an oracle under `oracle/` and a `SHA256SUMS` of the oracle files.

| Tool | Result (this machine) | Rerun |
|---|---|---|
| `shaders/` Maxwell to SPIR-V | 222 distinct stand-in blocks: Ryujinx harness 222 valid (206 first try, 16 after DebugMode retry), smo translator 135 valid, 0 spirv-val failures on either | `python shaders/oracle/run_oracle.py --dksh shaders/corpus/sascha_dksh --out <dir> --expect shaders/oracle/expected_sascha.json` |
| `textures/` ASTC to BC7 | 260 files: decode identical to astcenc, PSNR RGB min 34.65 / mean 51.95 dB, SSIM min 0.974, alpha exact, BCn passthrough exact; 5.9 MPix/s total, 6.5 MPix/s BC7 encode at preset 5 on 16 threads | `python textures/oracle/run_oracle.py --out <dir>` |
| `tiling/` block-linear | 332 cases from Ryujinx identical (20,455,125 blocks), 3 x ~5,900 synthetic textures round-trip and match an independent address formula | `python tiling/oracle/run_oracle.py` |

## Order of work

1. Read Wonder's TRANSLATOR.md / TILING.md and the harness; built `uam` 1.0.0 from source in WSL; fetched astcenc 5.7.0, ambientCG CC0 images and Sascha Willems' GLSL samples (parallel workers).
2. Ported the harness against a staged copy of `refs\ryubing`, added the DKSH route and the desktop host profile, built smo's translator as a batch tool, wrote the oracle (workers for the corpus builder, smo driver, oracle runner; the harness changes were done by hand).
3. Wrote the texture library and CLI, found the alpha problem (debug 002), picked the preset from a sweep and set the thresholds.
4. Wrote the tiling library; the first cross-check found the 3D mip rule error (debug 003). A worker built the Ryujinx reference generator and its independent Python verifier.
5. One test batch of all three oracles, one commit.

## Decisions the brief left open

- Stand-in shader corpus: `uam` compiling Sascha Willems' MIT GLSL samples (289 of 300 compile). Shader binaries in Ryujinx's repo and homebrew samples were not pursued: no official devkitPro deko3d example repo with shader sources exists on GitHub, and `uam` plus an open GLSL set gave a corpus we can regenerate.
- BC7 encoder: bc7e (Apache-2.0, ISPC), chosen for its licence and its reputation for speed with AVX2 over bc7enc_rdo's C++ encoder, Compressonator and ISPCTextureCompressor. It was not benchmarked against them. ISPC 1.32.0 is a build-time tool only.
- astcenc as three decode-only DLLs picked by CPUID (their static libraries export identical symbols and cannot be linked together).
- Default Ryujinx host profile is a desktop Vulkan 1.3 GPU (`--host moltenvk` keeps Wonder's). Default `spirv-val` target `vulkan1.3`.
- Opaque textures keep alpha exactly 255 at about 2 dB RGB PSNR cost (`docs/debug/002.md`).
- Default BC7 preset 5; thresholds 33 dB / 0.97 SSIM per file and 48 dB mean, justified in `textures/README.md`.
- Tiling linear rows are padded to 4 bytes by default (Ryujinx's convention); `linear_stride_align = 1` gives tight rows.

## Known gaps

- The smo translator hard-codes NVN's `c[2]` texture handle table; uam emits deko3d's layout, so 72 of its 87 failures on this corpus are texture handles. The Ryujinx-versus-smo pass-rate comparison that decides the translator needs the real game shaders.
- Ryujinx's translator drops `PRET` ("not implemented", 7 blocks) and one storage store seen in Wonder: translation is valid but not semantically complete.
- Stand-in shaders are compile-only: `build_corpus.py` renumbers bindings and rewrites subpass and multiview inputs.
- Textures: LDR only; no HDR ASTC, 3D ASTC or arrays in one call; Windows only (LoadLibrary). The stand-in images are 1K CC0 photographs of materials, not game art.
- Tiling: tile width above 1 (`gobBlocksInTileX`) and 3D arrays are untested; no BNTX parsing here (Wonder's `bntx.py` is the reference for reading the block height field).
- The tools repo has no top-level LICENSE file.
- Corpora and build products live in `work\corpus\` (ignored); the shader dksh corpus (444 KB) is committed so the oracle reproduces from the repo.
